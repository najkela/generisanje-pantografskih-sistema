# CLAUDE.md — упутство за рад на овом репоу

## 1. Пројекат

Генерисање пантографских механизама који описују задату криву. Дат је уређен скуп тачака
у равни (затворена изломљена линија); тражи се механизам чији tracer чвор, при пуној
ротацији crank-а, описује путању што ближу циљној кривој (Chamfer растојање).

Истраживачки пројекат за Петницу. Носећа хипотеза (H1): **bilevel** приступ
(ГА над топологијом + ЦМА-ЕС над геометријом) даје ниже коначне грешке и/или бржу
конвергенцију од **истовремене** оптимизације целог генома (чист ГА), при истом буџету
позива симулатора.

## 2. Језик

- **Разговор:** српски, ћирилицом, без персирања („ти", не „ви").
- **Кôд:** имена фајлова, модула, функција, класа и променљивих — **енглески**,
  `snake_case` за функције, `CapWords` за класе.
- **Коментари и докстрингови:** **српски, ћирилицом**.
- **Излаз програма** (поруке изузетака, логови, CLI помоћ, наслови графика) — **ћирилицом**;
  то види корисник.
- **Commit поруке:** српски, ћирилицом, у императиву.
- Публика документације је аутор и ментор: ЦМА-ЕС, bilevel оптимизација и Chamfer
  растојање се **не објашњавају од нуле**.

Термини из литературе (fixed, crank, tracer, floating, warm-start, solving order,
circuit defect) остају на енглеском и у коду и у коментарима — не преводити их у ходу.

## 4. Кључне конвенције (сажето; пуна дефиниција у README)

**Индекси чворова** (README 1.3) — улога је одређена искључиво индексом:

| Индекс | Улога |
|---|---|
| 0 | fixed, закуцан у (0,0) |
| 1 | fixed, геометријски слободан (носи ротацију и скалирање механизма) |
| 2 | crank, обавезна ивица (0,2), никад везан за чвор 1 |
| n−1 | tracer |
| остали | floating, укупан степен ≥ 2 |

- Димензионалност континуалног вектора: **2n−2** (све координате осим чвора 0), исто за оба
  метода.
- Валидација топологије (README 1.4), редослед јефтино → скупо: структурне провере →
  провера степена → провера ослонца crank-а → провера инваријанте редоследа
  (за сваки чвор `k ≥ 3`: тачно 2 суседа мањег индекса; измењено 31.08., замењује BFS
  претрагу и повлачи tie-break као беспредметан) → провера да се solving order
  завршава tracer-ом. DOF=1 се обезбеђује имплицитно. Формула је `DOF = 2(n−2) − j`,
  дакле `j = 2n−5`; Грублеров облик `3(n−1) − 2j` је погрешан за наш начин бројања
  (n = зглобови, j = полуге). Ивица (0,1) не постоји — оба чвора су на подлози.
- **„укупан степен ≥ 2"** је услов укупног степена; **„тачно 2 суседа мањег индекса"** је
  услов решивости. То нису исте провере (исправка 07.08., преформулисано 31.08.).
- Сваки оператор — постојећи и будући — мора одржати инваријанту редоследа. Оператор који
  је прекрши чини канонизацију вишезначном и обара валидацију.
- Нормализује се циљна крива при учитавању (центар bounding box-a → (0,0), највеће растојање
  од центра → 1), и **исто тако и генерисана путања при свакој евалуацији** (ревидирано
  02.09., в. README 1.5). Фитнес мери искључиво облик; поза се на крају покретања враћа
  сличносном трансформацијом координата најбољег генома. Циљна крива се подузоркује на
  текуће N (`curve.resample`), да оба скупа буду исте густине.
- Фитнес: симетрично Chamfer растојање, `scipy.spatial.cKDTree` над циљном кривом (гради се
  једном). Невалидне топологије/геометрије добијају **велику коначну казну**, никад
  `inf` и никад `nan` — ЦМА-ЕС мора остати стабилан.
- Јединица трошка је **позив симулатора**, не генерација. Baseline: 1 јединка = 1 позив.
  Bilevel: 1 евалуација топологије = стварно потрошен K позива унутар ЦМА-ЕС-а.
- Улоге се изводе из позиције у секвенци склапања (измењено 30.08.): fixed = позиције 0 и 1,
  crank = позиција 2, tracer = **последња** позиција. Fixed и crank су непроменљиви; tracer
  прати крај секвенце, па га `add_node` начин А помера. Мутација никад не додељује улоге директно.
- Невалидна мутација → јединка остаје у популацији са казном; мутација се **не понавља**
  док не испадне валидна.

## 5. Структура репоа

```
README.md                  формална дефиниција проблема (Део I–IV)
CLAUDE.md                  овај фајл
run.py                     CLI улазна тачка
pantograph/                пакет
  genome.py                структуре генома, вектор ↔ чворови, дужине кракова
  validation.py            провере топологије + инваријанта редоследа
  simulator.py             forward kinematics, пресек кругова, путања tracer чвора
  curve.py                 учитавање, нормализација, подузорковање, KD-дрво
  fitness.py               Chamfer растојање, казне
  operators.py             мутациони оператори (тополошки и координатни), иницијализација
  baseline.py              baseline: чист ГА над монолитним геномом
  bilevel.py               наш метод: спољашњи ГА + унутрашњи ЦМА-ЕС
  experiment.py            буџет, метрике, семе, логовање, плато-детекција
  visualization.py         анимација механизма, цртање путање
tests/                     pytest
data/curves/               улазне циљне криве (720 тачака по фајлу)
results/                   логови и излази експеримената (не иде у гит)
docs/                      закључане одлуке, отворена питања, BASELINE_SPEC.md
помоћни фајлови/           литература, стари дневници, белешке
simulator.py               ПРОТОТИП са хардкодованом топологијом — референца, не користи се
```

`simulator.py` у корену је оригинални прототип из јула; служи као референца за
`smart_intersect` хеуристику и solving order. Нови кôд иде у `pantograph/`.

## 6. Окружење и команде

Свака bash команда се покреће у новом shell-у, па `source .venv/bin/activate` **не остаје**
између позива. Увек зови интерпретер из venv-а директно:

```bash
.venv/bin/python -m pytest                          # сви тестови
.venv/bin/python -m pytest tests/test_curve.py -v   # један фајл
.venv/bin/python run.py --help
.venv/bin/python -m pip install -r requirements.txt
```

Зависности: `numpy`, `scipy`, `matplotlib`, `cma`, `pytest`.

## 7. Стил кода

- Python 3.12+, типске анотације на свим јавним функцијама.
- Докстринг: једна реченица на српском + референца на секцију README-а где је ствар
  формално дефинисана (нпр. `README 1.4`).
- Тестови у `tests/` су спецификација, не накнадна провера. Функције из скелета су
  означене `pytest.mark.xfail(raises=NotImplementedError)` — кад се имплементира,
  ознака се уклања.
- NumPy векторизација где има смисла; симулатор је најтоплија петља у пројекту.
- Никаквих скривених глобалних стања осим експлицитног `CallCounter`-а.
- Не мењај потписе функција из скелета без договора — они прате README.

## 9. Notion — дневник рада

Workspace је већ постављен. **Не праве се нове базе или странице** осим на изричит захтев.

- База „Дневник рада": `d337aaf5-c922-40cc-9c2e-cde3f2f8f994`
- Страница „Одлуке и архитектура": `3a8bdb69-5d57-8146-9d9c-c46199d1fd6b`
- Централна страница „Дневник рада": `3a8bdb69-5d57-818d-bde8-c39a6d581898`

Шема базе (тачни називи колона):

| Својство | Тип | Напомена |
|---|---|---|
| Тема сесије | title | обавезно |
| Датум и време | date, `is_datetime: 1` | нпр. `2026-08-29T19:00:00` |
| Статус | select | Нацрт / Финализирано |
| Фаза пројекта | select | Теорија / Архитектура / Имплементација / Резултати |
| Има нове одлуке | checkbox | `__YES__` / `__NO__` |

Садржај сваког уноса, тим редом: `## Дискусија`, `## Одлуке`, `## Отворена питања`,
`## Наредни кораци`. Одлуке се означавају као `**ОДЛУКА — назив:** опис`.

Правила:
1. Пре сваке измене или уноса у Notion — изричита дозвола од Николе. Одобрење из претходне
   сесије не важи за следећу.
2. На крају радне сесије или кад се донесе одлука — **предложи** унос, немој уписати без
   потврде садржаја.
3. После финализованог уноса са новом одлуком — предложи и ажурирање табеле у
   „Одлуке и архитектура".

Команда `/journal` припрема нацрт уноса из тока текуће сесије.
