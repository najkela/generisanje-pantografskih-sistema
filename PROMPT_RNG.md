## Целина А — записати одлуке (само документација, без кода)

**А1 — Границе ρ у ЦМА-ЕС вектору.** Горња и доња граница за ρ димензије се ПРОШИРУЈУ
(`cma_rho_lower` 0.05 → 0.01, `cma_rho_upper` 20.0 → 100.0) тако да их оператори не могу
пробити, а `clip` почетне тачке уведен 05.09. у `_construct_cma_es` се УКЛАЊА. Разлог:

нарушавао само оправдање warm-start-а („дете креће близу родитеља"). Уска граница није
радила никакав посао који већ не ради тврда граница гломазности (највећа полуга /
полупречник ≤ 5) — била је други појас преко истих панталона. Уместо да се питање решава
мерењем колико се често окида, уклања се узрок. ЦМА-ЕС и даље МОРА да има декларисане
границе (конструктор захтева почетну тачку унутар њих), само оне више нису активно
ограничење.

## Целина В — РНГ за ЦМА-ЕС

Две независне измене које иду заједно. Немој да урадиш само једну.

### В1 — предаја: сопствени `randn` уместо snapshot-а legacy стања

`cma` узорке вуче из глобалног legacy `numpy.random` стања, не из приватног генератора,
упркос томе што прима `seed`. Библиотека то САМА документује на
`evolution_strategy.py:1101`: `seed` се користи само док је `randn` подразумевани.

Провера изворног кода cma 4.4.4 (урађена 05.09., не понављај је осим ако нешто не штима):
узорковање иде искључиво кроз `self.randn` у `sampler.py`; граничар `boundary_handler.py`
је детерминистичан; све остале појаве `np.random` у пакету су doctest-ови, коментари
унутар блокова, или опције које не користимо (TPA адаптација σ, целобројне променљиве,
стохастичко заокруживање).

Дакле:

```python
opts["randn"] = lambda lam, N: record.rng.standard_normal((lam, N))  # облик ТАЧНО (lam, N)
opts["seed"] = np.nan   # „не ради ништа" — гаси упозорење библиотеке
```

Последица коју треба спровести до краја: **`record.rng_state` и `_ask_isolated` се БРИШУ**,
не допуњују. Уз њих иде и свако снимање/враћање `np.random.get_state()/set_state()` у
`_construct_cma_es`. Разлог зашто брисање а не задржавање обоје: snapshot штити само
путеве које смо прегледали, па свака непрегледана путања остаје тиха рупа; уклањањем
зависности рупа престаје да постоји као категорија.

Провери при покретању да упозорење „seed=... will never be used" СТВАРНО не излази. Ако
ипак излази, нађи прави начин да се угаси — немој да гушиш излаз библиотеке.

### В2 — семе: позиционо уместо редног

Садашње `seed = int(rng_cma.integers(...))` извлачи семена РЕДОМ којим се записи стварају.
То значи да промена броја створених ЦМА-ЕС објеката (спољашња популација, третман
невалидне деце, `k_max`) помера токове СВИХ наредних топологија и ниједно раније
покретање није упоредиво ни са чим. То је тачно она грешка коју је одлука о четири тока
(30.08.) направљена да спречи, само на дубљем нивоу.

Замени тиме да генератор зависи од ПОЗИЦИЈЕ, не од историје:

```python
KLJUC_CMA = 5   # константа, да се не судари ни са чим другим изведеним из истог seed-а

def cma_rng(main_seed: int, generation: int, slot: int) -> np.random.Generator:
    return np.random.default_rng([main_seed, KLJUC_CMA, generation, slot])
```

**На почетку сваке спољашње генерације**, пре позива `inner_cmaes`, сваки запис добија
`record.rng = cma_rng(main_seed, generation, slot)`, где је `slot` његово место у
спољашњој популацији те генерације. Тако бројеви које запис потроши у генерацији *g*
зависе САМО од `(seed, g, slot)` — не од тога колико је објеката створено пре њега.

Запис живи кроз генерације (живо ЦМА-ЕС стање, §22) и то остаје нетакнуто — мења се само
одакле му долазе нормале у датој генерацији. ЦМА-ЕС-у је свеједно, њему треба низ
независних стандардних нормала.

Пети спawn-овани ток `rng_cma` тиме постаје непотребан: `spawn_rng_streams` се враћа на
четири тока и опциони `n_streams` се уклања ако га ништа друго не користи. Пошто је
`SeedSequence.spawn` детерминистичка по редном броју, прва четири тока остају
бит-идентична — али то се ДОКАЗУЈЕ регресијом (целина Г), не претпоставља.

### Ограничење које уписујеш у DECISIONS и не преувеличаваш

Позиционо семе НЕ даје пуну упоредивост кроз верзије кода, јер која топологија седи на
ком месту зависи од селекције, дакле од фитнеса, дакле се и то мења. Уклања се ТИХА
СПРЕГА (промениш нешто концептуално неповезано и све се помери), не постиже се гаранција.

## Целина Д — тестови

Уз постојећих 6 у `tests/test_bilevel.py`, додај:

1. **Детерминизам:** два узастопна `outer_ga` са истим seed-ом → бит-идентичан `RunLog`,
   укључујући `best_genome.coords`.
2. **Изолација од глобалног стања (кључни тест — овај доказује целу измену В1):** два
   `outer_ga` са истим seed-ом, али између њих потроши глобални `np.random`
   (нпр. `np.random.seed(12345); np.random.randn(1000)`) → резултат МОРА остати
   бит-идентичан. Пре измене овај тест пада; после мора да прође.
3. **`np.random.seed` се не позива:** monkeypatch-уј `np.random.seed` да диже изузетак,
   покрени кратак bilevel, провери да не окине. Ово директно погађа конструкцију.
4. **Позиционо семе је стабилно:** `cma_rng(s, g, k)` даје исти низ у два одвојена
   конструисања, независно од редоследа позива; различити `(g, k)` дају различите низове.
5. **ρ ван граница** — в. целина Б.
