### 1.2. Механизам укрштања за baseline монолитни геном — ЗАТВОРЕНО 30.08.

> **Одлука:** рез секвенце склапања. Пун опис у README 2.2 („Укрштање — рез секвенце склапања") и `docs/BASELINE_SPEC.md` §5.

- **Контекст:** генерацијска шема baseline-a је закључана (20% елите непромењено; 80% из
  укрштања по расподели 30/30/20), а мутација је затворена одлуком од 09.08. Али **шта
  укрштање заправо ради са две топологије** нигде није дефинисано. За два графа са различитим
  бројем чворова и различитим скуповима ивица, „укрштање" није очигледна операција.
- **Зашто је отворено:** превиђено — шема укрштања је преузета из оригиналног предлога, где
  геном није био граф променљиве величине.
- **Шта треба одлучити:**
  - Шта се наслеђује од ког родитеља кад се број чворова разликује (нпр. основа је мањи
    родитељ па се додају чворови већег? унија ивица над заједничким подскупом чворова?).
  - Како се координате комбинују за чворове које оба родитеља имају (интерполација? избор
    једног родитеља по чвору?).
  - Да ли резултат мора бити валидан по конструкцији, или пролази кроз исту казну као
    невалидна мутација (README 1.4).
- **Ограничење фер поређења:** ово директно одређује колико је baseline јак. Прослаб
  механизам укрштања чини H1 поређење бесмисленим — baseline мора бити best-effort.
- **Блокира:** `pantograph/baseline.py::crossover` и `::evolve`, дакле половину H1
  експеримента.
- *Референца: README 2.2.*

## Приоритет 2 — механизам bilevel метода (треба пре пуне имплементације)

### 2.1. Механизам наслеђивања геометрије при додавању чвора (warm-start) — ДЕЛИМИЧНО ЗАТВОРЕНО 30.08.

> **Затворено:** избор ослонаца и почетна позиција новог чвора, за оба начина `add_node`-а
> (README 2.3, `docs/BASELINE_SPEC.md` §4). Тиме је **baseline одблокиран**.
>
> **Остаје отворено (само bilevel):** како нови пар координата улази у почетну средину
> ЦМА-ЕС расподеле и са којим почетним σ за нове димензије; и да ли мртви чворови заузимају
> димензије ЦМА-ЕС вектора или се изостављају.

- **Контекст:** warm-start је закључан као принцип — ЦМА-ЕС наслеђује геометрију родитеља
  уместо насумичне иницијализације. Али при операцији **додај чвор**, нови floating чвор
  нема родитељску позицију.
- **Зашто је отворено:** означено „механизам при додавању чвора — отворено" још од 10.07.
- **Шта треба одлучити:**
  - Између којих тачно постојећих чворова се интерполира позиција новог чвора (нови чвор се
    везује за 2 постојећа — да ли је почетна позиција средина та 2, или нешто друго).
  - Како се тај нови пар координата убацује у ЦМА-ЕС почетну средину и са којим почетним σ
    за нове димензије.
- *Референца: README 2.4, 4.5. Кôд: `pantograph/bilevel.py::warm_start`,
  `pantograph/operators.py::add_node`.*

## Приоритет 3 — калибрација (може паралелно са раним експериментима)

### 3.1. Прагови плато-детекције (W, ε)

- **Контекст:** исти механизам плато-детекције користи се на **три места**: динамички N
  (резолуција), динамички K (спрега), критеријум заустављања.
- **Шта треба одлучити:**
  - Величина клизног прозора W и праг ε — засебно за свако од три места (не морају бити исти).
  - За динамички N: распоред раста 90 → 720 (корак/крива раста).
- *Референца: README 2.4, 4.2. Кôд: `pantograph/experiment.py::plateau_detected`,
  `::resolution_schedule`.*

### 3.2. Референтне фиксне вредности K

- **Контекст:** динамички K је примарна верзија; фиксне вредности 5/15/40 служе као
  референтна основа за поређење (H3).
- **Шта треба одлучити:** да ли ове три вредности остају репрезентативан распон или их треба
  ревидирати након првих експеримената.
- *Референца: README 2.4, 3.5, 4.5.*

### 3.3. Иницијализација — бројеви — ПОЧЕТНЕ ВРЕДНОСТИ ПОСТАВЉЕНЕ 30.08.

> Конструктивни поступак и почетни опсези закључани (README 4.1). Остаје емпиријска
> калибрација самих бројева.

- **Шта треба одлучити:**

    (утиче на почетне дужине кракова и брзину конвергенције).
- *Референца: README 4.1. Кôд: `pantograph/operators.py::random_initial_coords`.*

## Приоритет 4 — коректност симулације (треба пре поузданих резултата)

### 4.1. Circuit defect провера

- **Контекст:** circle-circle пресек има 2 решења; тренутна хеуристика (`smart_intersect`)
  бира грану ближу претходној позицији. Код малог N (велике ротације по кораку) може настати
  **испрекидана путања** — нефизички скок између грана.
- **Шта треба одлучити:**
  - Да ли се таква путања **одбацује** (третира као неважећа геометрија → коначна казна) или
    само **казни** пропорционално.
  - Како се детектује скок (нпр. праг на растојању између узастопних позиција tracer-a).
  - Да ли се ослањамо на растуће N да проблем природно нестане, или уводимо експлицитну
    проверу независно од N.
- *Референца: README 4.4. Кôд: `pantograph/simulator.py::circle_intersect`.*
