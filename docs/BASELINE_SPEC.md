## 0. Упозорење пре прве линије кода

Тестови у `tests/` писани су као спецификација **старије** верзије README-а. Део њих сада
кодира одлуке које су оборене 30.08. и активно ће водити имплементацију у погрешном смеру:

- тестови за операторе `add_edge` / `delete_edge` — **ти оператори више не постоје**;
- тестови који тврде да се tracer улога никад не мења — **сада се мења**;
- свака провера DOF-а по формули `3(n−1) − 2j` — **та формула је погрешна**; важи `DOF = 2(n−2) − j`, дакле `j = 2n − 5`.

Уз то, једна конкретна грешка коју треба исправити у `tests/conftest.py`:

> **`fourbar` fixture има једну ивицу вишка.** Тренутно је
> `edges=[(0,2), (0,1), (1,3), (2,3)]` — четири ивице за `n = 4`, док је тачно `j = 2n − 5 = 3`.
> Ивица `(0,1)` не постоји: чворови 0 и 1 су **оба** закуцана за подлогу, па је веза међу
> њима сама подлога, а не полуга, и не улази ни у `E` ни у `j`. Исправно је
> `edges=[(0,2), (1,3), (2,3)]`.
>
> То није нова одлука — README 1.4 је већ рачуна тако (језгро `{0,1,2}` има `j = 1`, само
> ивицу `(0,2)`, одакле `DOF = 2(3−2) − 1 = 1`). Fixture је писан по старој Грублеровој
> формули, по којој је четири ивице давало `DOF = 1`. Са исправљеним fixture-ом BFS и даље
> ради: `known = {0,1,2}`, чвор 3 има суседе `{1,2}` — оба позната — solving order је `[3]`
> и завршава се tracer-ом, како провера 5 захтева. Чвор 1 остаје степена 1, што је дозвољено
> јер услов „степен ≥ 2" важи само за floating чворове.
>
> Ово повлачи и `test_link_lengths_from_initial_geometry` (тврдња о `(0,1)` испада) и
> `test_neighbors_and_degree` (`neighbors(0)` постаје `{2}`, `degree(0)` постаје 1).

**Корак 0 је ажурирање тестова.** Ниједан имплементациони корак не сме почети пре тога.

## 1. Секвенца склапања — канонски облик

Геном (`{n_nodes, edges, coords}`) памти *резултат* склапања. Из скупа ивица се не види ко
на кога виси: ивица `(3,5)` не каже да ли је чвор 5 решен помоћу чвора 3 или обрнуто.

За укрштање и операторе користи се **изведени** запис:

```
S = [0, 1, 2, u_3, u_4, ..., u_{n-1}]        # последњи елемент је увек tracer
```

За сваки `k ≥ 3`:

```
g_k = (a_k, b_k, rho_a_k, rho_b_k, s_k)
```

| Поље | Тип | Значење |
|---|---|---|
| `a_k`, `b_k` | int | **позиције у секвенци** два ослонца; `a_k != b_k`, оба `< k` |
| `rho_a_k` | float | `dužina(u_k, a_k) / D_k` |
| `rho_b_k` | float | `dužina(u_k, b_k) / D_k` |
| `s_k` | ±1 | која грана circle-circle пресека важи у `θ = 0` |

где је `D_k = ||q0(a_k) − q0(b_k)||`.

Геометрија језгра — `q0(0) = (0,0)`, `q0(1)`, `q0(2)` — носи се **дословно**, у апсолутним
координатама. Она даје скалу и оријентацију целе јединке.

### 1.1. КРИТИЧНО: односи важе само у `θ = 0`

`rho_*` и `D_k` су **алат за кодирање**, активни у тачно два тренутка:

1. при канонизацији — из геометрије се читају односи;
2. при реконструкцији — из односа се **једном** израчунају апсолутне дужине
   `l = rho * D_k`, где је `D_k` размак ослонаца **у `θ = 0`**.

Од тог тренутка `l` је константа и симулација је више не додирује. Полуге су круте.

Ово није ситница. Два ослонца истог чвора **не морају бити повезана ивицом**, па се њихов
размак током окретања crank-а мења. Ако размак порасте изнад збира двеју полуга, кругови се
више не секу → *circuit defect* → казна. То је исправно понашање; реалан механизам би се у
том положају заглавио.

Погрешна имплементација — она која у сваком `t` рачуна `l = rho * D_k(t)` — ту грешку никад
не би пријавила, јер би полуге ћутке мењале дужину и механизам би „радио" увек, а фитнес би
био број без физичког значења.

### 1.2. Једнозначност — инваријанта редоследа (измењено 31.08.)

Сваки чвор `k ≥ 3` настаје качењем на два већ постојећа чвора, и ниједан оператор то не
крши (§4). Одатле:

> **Инваријанта:** за сваки чвор `k ≥ 3`, скуп суседа мањег индекса има тачно 2 елемента.

Док она важи, редослед решавања је увек `[3, 4, ..., n-1]`. Канонизација је једнозначна
сама по себи, па је **раније прописан tie-break повучен као беспредметан.**

Ослонци чвора `k` се читају директно: `sorted(m for m in neighbors(k) if m < k)`.
Нема претраге.

## 2. DOF и валидација

```
DOF = 2(n − 2) − j        =>        DOF = 1  <=>  j = 2n − 5
```

`n` = број чворова (зглобова), `j` = број ивица (полуга). Број ивица је **потпуно одређен**
бројем чворова.

Валидација, редом (јефтине провере прво):

1. структурне — без self-loop, без дуплираних ивица, без изолованих чворова;
2. степен — тачно 2 fixed, тачно 1 crank, сваки floating чвор укупног степена ≥ 2;
3. ослонац crank-а — тачно једна ивица `(crank, fixed)`, и то мора бити `(0,2)`;
4. **инваријанта редоследа** (измењено 31.08.) — за `k` од 3 до `n−1`,
   `|{m ∈ neighbors(k) : m < k}| == 2`; мање → чвор неодређен, више → преодређен →
   неважеће. Solving order је тада тривијално `[3, …, n−1]`, не тражи се;
5. **положај tracer-a** — solving order се мора завршавати чвором `n−1`. Ако се tracer
   реши раније, топологија је неважећа.

Провера 5 је нова (30.08.). Разлог: чвор који виси на tracer-у је низводни привезак и не
утиче на путању, па се ништа не губи његовим искључивањем, а запис постаје једнозначан.

> **Зашто провера 4 остаје иако не може да падне за геном из оператора.** `Topology` је
> обичан скуп ивица и склапа се и ручно — у тестовима, у `run.py demo`, сутра у
> `bilevel.py`. Провера више не тражи редослед него потврђује да оператори одржавају оно
> што су дужни. Оператор са грешком у преспајању овде пада; тривијално враћен редослед
> `[3, ..., n-1]` не би.

## 3. Улоге

Улоге **нису независни гени**. Изводе се из позиције у секвенци:

- `fixed` = позиције 0 и 1
- `crank` = позиција 2
- `tracer` = **последња** позиција

`fixed` и `crank` су апсолутно непроменљиви. `tracer` прати крај секвенце.

Ово замењује раније правило „улоге се никад не мењају мутацијом" (16.07.).

## 4. Мутациони оператори

Оператора има **два**, оба над чворовима. Ивичних оператора нема — ивице настају и нестају
искључиво заједно са чвором.

**Сваки оператор мора одржати инваријанту редоследа из §1.2** — после потеза сваки чвор
`k ≥ 3` има тачно два суседа мањег индекса. Ово важи и за сваки оператор који се дода
касније.

### 4.1. `add_node`, начин А — допиши на крај

Нови чвор се дописује на **крај** секвенце и тиме постаје tracer; дотадашњи tracer постаје
обичан floating чвор.

- **Први ослонац је обавезно дотадашњи tracer.**
- Други ослонац се бира равномерно међу свим осталим претходним позицијама.
- Позиција: нови чвор се поставља на растојању `r = alpha * L` од старог tracer-a, у правцу
  насумичном равномерно по углу, где је `L` просечна дужина полуге те јединке (иста скала
  коју користи и координатна мутација) а `alpha ~ U(0.10, 0.40)`.
- Из добијене тачке се израчуна друга полуга до другог ослонца, па се изведу
  `rho_a, rho_b, s`.

**Зашто обавезан ослонац на старом tracer-у.** Нови tracer је крутом полугом дужине `r`
везан за стари, дакле у сваком тренутку је на растојању тачно `r` од њега. Његова путања
целом дужином лежи унутар растојања `r` од родитељске путање, па је Chamfer грешка детета
ограничено близу родитељској. То је права warm-start особина: `add_node` додаје способност
не рушећи фитнес.

**Зашто `alpha` има доњу границу.** При `alpha -> 0` нови чвор пада на стари и геометрија
постаје нумерички осетљива.

### 4.2. `add_node`, начин Б — убаци пре tracer-a

Нови чвор се убацује на место **непосредно пре** tracer-a. Tracer остаје исти.

- Оба ослонца се бирају равномерно међу свим позицијама пре места убацивања.
- Позиција: `rho_a, rho_b ~ U(0.7, 1.3)`, грана `s` насумична.

**Ово је неутрална мутација** — на нови чвор нико не виси и он није tracer, дакле није
предак tracer-a и **фитнес се не мења уопште**. То није грешка него сврха: тако настаје нова
грана коју каснији потез начина А може да споји са главном граном, чиме настају праве
рачвасте конструкције. Без овога свака јединка би била ланац у ком сваки чвор виси на свом
непосредном претходнику, и рачвање + спајање не би било достижно.

**Зашто баш непосредно пре tracer-a.** Пошто на нови чвор нико не виси, његово место у
секвенци је небитно све док је после својих ослонаца и пре tracer-a. Фиксирањем места
уклања се један сувишан параметар без губитка простора.

**Зашто распон `U(0.7, 1.3)`.** Троугао има странице `rho_a*D`, `rho_b*D` и `D`. Збир прве
две је најмање `1.4D > D`, а разлика највише `0.6D < D` — неједнакост троугла увек важи,
и увек са резервом од сингуларитета. Ако се у пракси покаже да превише јединки пропада,
распон се шири.

### 4.3. `delete_node`

Брише се чвор са позиције биране равномерно из `{3, ..., n-1}` (укључујући tracer);
захтева `n >= 5`.

За сваког зависника `w` чији је један ослонац обрисани чвор `u`:

- нови ослонац `r` бира се **равномерно насумично** из `{a_u, b_u} \ {y_w}`, где је `y_w`
  други (незахваћени) ослонац чвора `w`;
- чвор `w` **задржава своју позицију** у `θ = 0`; односи `rho_a_w, rho_b_w` се
  пресрачунавају из нових ослонаца.

Ако је обрисан последњи чвор, нови последњи постаје tracer.

**`r` увек постоји:** `a_u != b_u`, па највише један од њих може бити једнак `y_w`.
Тиме је искључен дегенерисан случај да чвор виси двапут на истом ослонцу.

**`DOF` остаје 1:** губе се 1 чвор и 2 ивице; по зависнику једна ивица се брише а једна
додаје (нето 0). `n' = n−1`, `j' = j−2` → `DOF' = 2(n−3) − (j−2) = 2(n−2) − j = DOF`.

**Последица избора „задржава позицију":** у `θ = 0` мења се тачно једна ствар — обрисани
чвор нестане, сви остали остају где су били. Мења се кретање, не почетни облик.

### 4.4. Мртав терет

Чворови ван предачког стабла tracer-a не утичу на путању. Настају природно (начин Б, и
понекад `delete_node`) и **не кресају се током претраге** — они су материјал који каснији
потез може да искористи.

Две последице за имплементацију:

- **Симулатор за рачунање фитнеса решава само претке tracer-a.** Мртве гране се не рачунају,
  па не коштају ништа у времену. (Пуна геометрија се рачуна само за приказ.)
- **`prune_dead_nodes()` постоји као засебна функција** која се позива **само** над коначним
  резултатом, за приказ и извештај. Никад унутар петље.

## 5. Укрштање — рез секвенце склапања

За родитеље `A` (`n_A` чворова) и `B` (`n_B`):

1. Рез `c ~ U{3, ..., min(n_A, n_B) − 1}`.
2. Дете = геометрија језгра од `A` + гени `g_3..g_{c-1}` од `A` + гени `g_c..g_{n_B-1}` од `B`.
3. Реконструкција: пролаз кроз секвенцу унапред; у сваком кораку позиција се рачуна
   circle-circle пресеком са полупречницима `rho_a*D_k` и `rho_b*D_k`, узимајући грану `s_k`.
   `D_k` је размак ослонаца у **реконструисаној `θ=0` геометрији детета**; добијене дужине се
   одмах фиксирају као константне полуге (1.1).

**Дете је структурно валидно по конструкцији.** Сваки ген показује уназад (`a_k, b_k < k`),
па ген преузет од `B` тражи позиције које дете већ има — само су на њима сада `A`-ови
чворови. Може пасти само на circuit defect током симулације → стандардна казна, **без
поправке**.

- `n_дете = n_B`; реципрочно дете (замена улога родитеља) има `n_A`.
- Tracer се наслеђује сам од себе: реп долази од `B` и завршава се `B`-овим tracer-ом.
- Скала долази од `A`-овог језгра; `B`-ов реп је у односима па се сам прилагоди. Никакво
  Procrustes поравнање ни мешање координата није потребно.
- Гранични случај `min(n_A, n_B) <= 4`: нема легалног реза → дете = копија `B` са `A`-овим
  језгром.

## 6. Генерацијска шема

- 20% најбоље оцењених прелази **непромењено** (елита).
- Преосталих 80% настаје укрштањем:
  - 30% деца два родитеља из горњих 20%
  - 30% деца из мешовитог пара горњих 20% и средњих 20–80%
  - 20% деца из средњих 20–80%
- Мутацији су подложне **само новонастале (укрштене) јединке**, не и елита.

При популацији 100 ово даје тачне целе бројеве: 20 елите, па 30 / 30 / 20.

### 6.1. Мутација новонастале јединке

Два независна „бацања новчића" (закључано 09.08.):

- са вероватноћом `p_topo` → тополошка мутација (избор оператора по 7.);
- са вероватноћом `p_coord` → координатна мутација.

Могу се десити обе, једна или ниједна.

**Координатна мутација:** сваки чвор осим чвора 0 независно, са gene-wise вероватноћом,
добија `Δ ~ N(0, sigma^2 I)` на тренутну позицију, где је `sigma = k * L`, а `L` просечна
дужина полуге те јединке **у тренутку мутације**. Коефицијент `k` опада кроз покретање.

## 7. Бројеви

Све су ово **почетне вредности за калибрацију**, не коначне. Држати их на једном месту у
коду (нпр. `pantograph/config.py` или дата-клас), не расуте по модулима.

| Параметар | Вредност |
|---|---|
| Величина популације | `100` |
| Укупан буџет по покретању | `50_000` позива симулатора, идентично за оба метода |
| Почетно `n` | равномерно из `{5, 6, 7, 8}` |
| Горња граница `n` | `12` |
| Доња граница `n` | `4` |
| `p_topo` | `0.30` |
| `p_coord` | `0.70` |
| Избор оператора | `add_node` начин А `0.40` / начин Б `0.25` / `delete_node` `0.35` |
| — ако је `n >= 12` | форсирај `delete_node` |
| — ако је `n <= 4` | форсирај `add_node` |
| Gene-wise вероватноћа (координатна мутација) | `0.25` |
| `k` (скала координатне мутације) | `0.15 → 0.02`, експоненцијално по потрошеном буџету |
| `alpha` (4.1) | `U(0.10, 0.40)` |
| `rho` при убацивању (4.2) и иницијализацији | `U(0.7, 1.3)` |
| Казна за невалидну јединку | `1e9` |
| Одсецање валидног фитнеса | `1e8` |
| Распоред `N` | `90 → 180 → 360 → 720`, напредује на плато |
| `W` / `eps` за напредовање `N` | `15` генерација / `1%` релативног побољшања најбољег |
| `W` / `eps` за заустављање (на `N = 720`) | `30` генерација / `0.1%` |

**Зашто одсецање фитнеса на `1e8`.** Генерисана путања се не нормализује, па дивља јединка
може дати огроман Chamfer. Без одсецања може се десити да валидна јединка буде оцењена
**горе** од невалидне, што тихо квари селекцију. Уз одсецање је невалидна увек строго гора.

**Напомена о буџету.** Ранија формулација „максимални буџет 150" односи се на горњу границу
броја ЦМА-ЕС итерација `K` по процени једне топологије у bilevel методу, не на укупан буџет
покретања. Укупан буџет је `50_000` позива симулатора и он је заједничка јединица поређења.

## 8. Иницијализација

Почетна јединка се генерише **преко секвенце, не преко координата**:

1. Језгро: чвор 0 у `(0,0)`; чвор 1 у `U(-1.5, 1.5)^2`; crank на растојању `U(0.2, 0.8)` од
   чвора 0, под насумичним углом.
2. Затим `n − 3` пута: изабери два ослонца међу постојећим позицијама, повуци
   `rho_a, rho_b ~ U(0.7, 1.3)` и грану `s`, допиши чвор на крај.

Тако је свака почетна јединка геометријски здрава по конструкцији и валидна по 2.

Опсег координата је везан за то да је циљна крива нормализована на полупречник 1 —
механизам распона ~2 јединице даје tracer-у простора да опише криву те величине.

## 9. Seed и логовање

**Један главни seed по покретању.** Из њега се изводе **четири независна тока** преко
`numpy.random.SeedSequence.spawn`:

```
rng_init      # иницијализација популације
rng_select    # селекција родитеља
rng_cross     # избор реза при укрштању
rng_mut       # избор оператора, ослонаца, alpha, rho, s, gene-wise новчићи
```

**Зашто одвојени токови, а не један.** Ако се све вуче из истог тока, додавање једног новог
насумичног избора било где помера све касније вредности, и покретања са истим seed-ом
престају да буду упоредива између верзија кода. Са одвојеним токовима, промена у мутацији
не помера иницијализацију. Кошта три линије сада; накнадно се не може уградити без губитка
свих ранијих резултата.

**Логује се по покретању:** главни seed, git commit hash, све вредности из табеле 7, путања
и hash фајла циљне криве, по генерацији (најбољи фитнес, средњи фитнес, потрошено позива
симулатора, тренутно `N`, тренутно `n` најбоље јединке), и најбољи геном на крају.

Ово је минимални део питања 5.1 — довољан да покретања буду поновљива. Остатак (шта тачно
улази у извештај за метрику конзистентности) остаје отворен.

### Корак Д — `run.py demo` (одлучено 30.08.)

Између корака 1.2 и 2.1 умеће се тачка заустављања која **није имплементација него провера
разумевања**. Скрипта `run.py demo`:

1. склопи један конкретан механизам са задатим координатама (не насумичан);
2. одврти crank кроз пуних 360°;
3. нацрта анимацију — полуге како се померају и путању коју tracer оставља за собом;
4. учита круг као циљну криву (ниво 1) и нацрта је преко тога;
5. испише Chamfer број.

Зависи само од `simulator.circle_intersect`, `simulator.simulate`, `curve.py`, `fitness.py`
и `visualization.py` — **не** од оператора, укрштања ни ГА.

**Зашто овде.** Све после ове тачке — оператори, укрштање, ГА — само је начин да се тај један
број спусти. Док се механизам не види како се окреће, остатак пројекта се гради као
апстракција. Ово је и тачка на којој се хвата највећа могућа грешка: ако се полуге развлаче
(в. §1.1), на анимацији се то одмах види, а на тестовима не мора.
