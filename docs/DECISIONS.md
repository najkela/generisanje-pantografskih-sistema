## 1. Проблем

Дат је уређен скуп тачака у 2Д равни. Циљна крива је **затворена изломљена линија**
добијена спајањем тачака редом (тачка i → i+1, последња → прва). Циљ: пронаћи пантографски
механизам чији **tracer чвор**, при пуној ротацији crank-а, описује путању која што ближе
прати циљну криву.

**Формат уноса (тренутно):** фајл са 720 тачака, свака у засебном реду, координате одвојене
зарезом.
**Формат уноса (каснији update):** GUI где корисник нацрта криву, програм извуче 720 тачака,
па downsample да се N поклопи.

## 2. Механизам и геном

**Комплетан опис механизма** = топологија (чворови, ивице, улоге) + геометрија (почетне
координате чворова, из којих се рачунају дужине кракова).

**Конвенција индекса (закључано):**

- индекси 0, 1 = fixed чворови
- индекс 2 = crank
- индекс n−1 = tracer
- обавезна ивица (0, 2)
- crank (2) везан искључиво за fixed чвор 0, никад за fixed чвор 1

**Две структуре генома** (оба метода описују ИСТИ простор решења):

Baseline (чист ГА) — монолитни геном:

```
genome_GA = { "n_nodes": int, "edges": [(i,j),...], "coords": {node: [x,y],...} }
```

Bilevel — раздвојено:

```
genome_topology = { "n_nodes": int, "edges": [(i,j),...] }   # спољашњи ГА, без координата
x = [x_1, y_1, ..., x_{n-1}, y_{n-1}]                        # унутрашњи ЦМА-ЕС, раван вектор
```

Мапирање вектор↔чворови мора бити детерминистичко и фиксно.

## 3. Геометријске конвенције и димензионалност

- fixed чвор 0 закуцан у (0,0) — уклања само транслацију.
- fixed чвор 1 потпуно слободан — контролише ротацију и скалирање целог механизма; ниједна
  координата се не фиксира.
- димензионалност континуалног вектора = **2·n_nodes − 2**, идентично за оба метода.
- механизам мора имати **DOF = 1** (Grübler–Kutzbach: DOF = 3(n−1) − 2j). Провера
  „тачно 2 позната суседа при решавању" имплицитно обезбеђује DOF=1.

## 4. Валидација топологије + solving order

Редослед провера (јефтине прво):

1. Структурне провере — без self-loop, без дуплираних ивица, без изолованих чворова.
2. Провера степена — тачно 2 fixed, тачно 1 crank, сваки floating чвор укупан степен
   **бар 2** (≥2, НЕ тачно 2 — да чвор може бити родитељ другом чвору → дубоки механизми).
3. Провера ослонца crank-а — тачно једна ивица crank→fixed.
4. Конструкција solving order-а (BFS): `known = {2 fixed} ∪ {crank}`; понављај — нађи
   floating чвор са **тачно 2 позната суседа**, реши га (circle-circle intersection),
   премести у known; ако пролаз не направи напредак → невалидно (циклична зависност).

Напомена: „бар 2" је услов укупног степена (нужан); „тачно 2 позната суседа" се проверава
у тренутку решавања унутар BFS-a (то је стварни услов решивости). Ова разлика је важна —
исправка од 07.08.

## 5. Фитнес функција — Chamfer дистанца

```
d(G,T) = (1/n) Σ_i min_j ||g_i - t_j||²  +  (1/m) Σ_j min_i ||t_j - g_i||²
```

- Симетрична (оба смера) — спречава дегенерисана решења.
- Инваријантна на смер и брзину обиласка (смер није битан за циљ пројекта).
- Убрзање: `scipy.spatial.cKDTree` над циљном кривом (грађен једном), O(n log m).
- Невалидне геометрије/топологије → велика КОНАЧНА казна (не бесконачност — ради ЦМА-ЕС
  стабилности).

## 7. Главна хипотеза (H1) и структура рада

**H1 (примарна, једина носећа):** Раздвајање претраге на bilevel структуру (ГА-топологија +
ЦМА-ЕС-геометрија) даје ниже коначне грешке и/или бржу конвергенцију од истовремене
оптимизације целог генома (чист ГА), при истом буџету евалуација, јер унутрашњи ЦМА-ЕС
експлицитно моделује спрегу континуалних параметара коју истовремени приступ третира као
независне.

**Теоријски извор:** Ong, Shirakawa & Akimoto (2026), *Mixed-Categorical Black-Box
Optimization via Information-Geometric Bilevel Decomposition* — методи који мешовите
categorical-continuous просторе третирају заједно губе перформансе кад постоје јаке
интеракције међу варијаблама.

**H2 и H3 нису независна истраживања** — демотиране у мотивисане имплементационе одлуке
унутар главног експеримента:

- H2: crossover vs. само-мутација топологије (default: само-мутација).
- H3: јачина спреге ГА↔ЦМА-ЕС, фиксни K vs. динамички K (default: динамички K).

## 8. Предмет поређења и метрике

- **Baseline:** чист ГА над целим геномом (истовремени приступ, ≈ оригинална замисао из
  првог предлога). Мора бити best-effort, не намерно ослабљен.
- **Наш метод:** bilevel (ГА-топологија + ЦМА-ЕС-геометрија + warm-start).
- **Метрике:** (1) коначна Chamfer грешка при истом буџету; (2) брзина конвергенције као
  функција **броја позива симулатора** (фер јединица трошка); (3) конзистентност
  (варијанса преко више seed-ова).
- **Буџет:** бројање на нивоу позива симулатора (једна bilevel евалуација топологије троши
  K позива унутра; једна baseline јединка троши 1). Почетно макс 150, мења се у ходу.

## 9. Механизам оптимизације — детаљи

- **Мутациони оператори (само-мутација):** додај чвор (нови floating, везан за 2 постојећа,
  warm-start позиција интерполацијом), обриши чвор, додај ивицу, обриши ивицу. Улоге
  (fixed/crank/tracer) се НИКАД не мењају мутацијом.
- **Невалидне мутације:** јединка остаје у популацији уз велику коначну казну; мутација се
  НЕ понавља до валидног генома.
- **Warm-start:** ГА при мутацији наслеђује/интерполира геометрију родитеља као почетну
  средину ЦМА-ЕС расподеле, уместо насумичне иницијализације.
- **Динамички N (резолуција криве):** плато-детекција (клизни прозор W, праг ε) — расте
  90→720 кроз генерације; кад је N=720 и плато траје, служи и као критеријум заустављања.
- **Динамички K (спрега):** плато-детекција унутар ЦМА-ЕС рана (early stopping).
  Референтне фиксне вредности за поређење: 5/15/40.

## 15. Секвенца склапања, укрштање и оператори (закључано 30.08.)

Извршни облик свих одлука из ове секције: `docs/BASELINE_SPEC.md`. Формално образложење: README 1.2.1, 1.4, 2.2, 2.3, 4.1–4.3.

**ОДЛУКА — DOF формула:** `DOF = 2(n−2) − j`, дакле `j = 2n − 5`. Ранија Grübler–Kutzbach формула `3(n−1) − 2j` је погрешна за наш начин бројања (n = зглобови, j = полуге) и важила је случајно само за n = 6.

**ОДЛУКА — ивица (0,1) не постоји:** чворови 0 и 1 су оба закуцана за подлогу; веза међу њима је подлога, не полуга, и не улази ни у `E` ни у `j`. Најмањи валидан механизам (n = 4) има три ивице.

**ОДЛУКА — секвенца склапања као канонски облик:** уведен изведени запис `S = [0,1,2,u_3,...,u_{n-1}]` са геном корака `(a_k, b_k, ρ_a, ρ_b, s_k)`. Односи важе искључиво у θ = 0; дужине се фиксирају једном при реконструкцији и симулација их не мења.

**ОДЛУКА — детерминистички tie-break у BFS-у:** при више кандидата бира се најмањи индекс чвора. Без овога канонизација није једнозначна и репродуцибилност пада. → **ПОВУЧЕНО 31.08., в. секцију 16.**

**ОДЛУКА — tracer је последњи у секвенци:** додата пета провера валидације. Ниједан чвор не сме висити на tracer-у.

**ОДЛУКА — улоге се изводе из позиције:** fixed = позиције 0 и 1, crank = позиција 2, tracer = последња позиција. Ово мења одлуку од 16.07. („улоге се никад не мењају мутацијом") — fixed и crank остају непроменљиви, али tracer прати крај секвенце. Без тога је `add_node` мртав потез.

**ОДЛУКА — укрштање је рез секвенце склапања:** дете = језгро од A + гени `g_3..g_{c-1}` од A + гени `g_c..g_{n_B-1}` од B. Дете је структурно валидно по конструкцији; пада само на circuit defect, без поправке.

**ОДЛУКА — два оператора, оба над чворовима:** ивични оператори (`add_edge`, `delete_edge`) укинути. `add_node` има два начина (А: допиши на крај, обавезан ослонац на дотадашњем tracer-у; Б: убаци пре tracer-a, неутрална мутација која омогућава рачвање). `delete_node` преспаја зависнике насумичним избором из ослонаца обрисаног чвора; чвор задржава позицију у θ = 0.

**ОДЛУКА — мртав терет се не креше током претраге:** чворови ван предачког стабла tracer-a остају у геному као материјал за касније потезе. Симулатор за фитнес решава само претке tracer-a. `prune_dead_nodes()` се позива само над коначним резултатом.

**ОДЛУКА — буџет:** укупно 50 000 позива симулатора по покретању, идентично за оба метода. Раније навођених „150" је горња граница за K (ЦМА-ЕС итерације по процени једне топологије), не укупан буџет.

**ОДЛУКА — четири RNG тока:** `rng_init`, `rng_select`, `rng_cross`, `rng_mut`, изведени из једног главног seed-а преко `SeedSequence.spawn`.

**ОДЛУКА — одсецање валидног фитнеса на 1e8, казна 1e9:** без одсецања валидна јединка може бити оцењена горе од невалидне.

## 16. Инваријанта редоследа замењује BFS (закључано 31.08.)

**ОДЛУКА — инваријанта редоследа:** за сваки чвор `k ≥ 3` важи да скуп његових суседа мањег индекса има **тачно два** елемента. То су ослонци чвора `k`.

**ОДЛУКА — валидација проверава инваријанту, не тражи редослед:** BFS претрага се укида. Solving order је увек `[3, 4, …, n−1]`, једнак редоследу индекса, па се не мора рачунати; ослонци чвора се читају као `sorted(m for m in neighbors(k) if m < k)`.

**ОДЛУКА — tie-break се повлачи:** одлука од 30.08. („при више кандидата бира се најмањи индекс чвора") постојала је само зато што BFS може имати више решења. Уз инваријанту избора нема, па је правило беспредметно и брише се. Канонизација је једнозначна сама по себи.

**ОДЛУКА — обавеза оператора:** сваки оператор, постојећи и будући, мора одржати инваријанту. Проверено да је одржавају: `random_initial_genome` и `from_sequence` (граде чворове редом, ослонци увек `< k`), `add_node` начин А (ослонци стари tracer и још један, оба `< n`), начин Б (ослонци из `range(old_tracer)`, стари tracer се помера на `n`), `delete_node` (`r ∈ {a_u, b_u}`, оба решена пре `u`, дакле пре сваког зависника).

**ОБРАЗЛОЖЕЊЕ ЗАДРЖАВАЊА ПРОВЕРЕ:** иако за геном произведен операторима провера не може да падне, `Topology` је обичан скуп ивица и склапа се и ручно — у тестовима, у `run.py demo`, сутра у `bilevel.py`. Провера више не тражи одговор него потврђује да оператори одржавају оно што су дужни. Оператор са грешком у преспајању овде пада; тривијално враћен редослед `[3, …, n−1]` не би.

**ПОРЕКЛО:** запажање Николе — ако се геном ионако гради чвор по чвор, редослед је већ садржан у самом запису и не мора да се тражи.

приговор и мерење, не кроз процену.

**ОДЛУКА — закуцана грана circle-circle пресека.** `simulator.positions_at` више не бира
грану по близини претходног положаја. За сваки чвор се једном, у θ=0, рачуна знак гране
(са које стране усмерене праве `a→b` лежи — то је `s` из `SequenceGene`, README 1.2.1) и
тај знак важи на сваком углу. `_closer_branch` се уклања са вруће путање.

Образложење: грана је својство склопа, не историје. Прелазак на другу грану захтева пролаз
кроз мртву тачку (`h = 0`, угао преноса 0°), коју праг угла преноса већ одбија. Прескок
постаје структурно немогућ, а конфигурација на углу θ зависи само од θ и вектора знакова.
Механизам који на својој грани нема решење се закочи → `None` → казна.

Мерено: не одбацује здраве јединке (310/397 тополошки валидних заврши пун обртај — исти
број са хеуристиком и са закуцаном граном). Успутна последица: Chamfer постаје монотона
функција од N и конвергира; са хеуристиком је скакао (за једну јединку 7.3e-02 → 8.3e-02 →
3.9e-02 → 2.3e-02 → 3.8e-02 за N = 90/180/360/720/2880, са минимумом баш на пријављеном
N=720, док иста јединка са закуцаном граном даје монотоно 4.1e-02 → … → 3.8e-02).

**Затвара отворено питање 4.1 (circuit defect)** — укидањем узрока, не увођењем провере.
Провера затварања конфигурације (сви чворови на θ=2π наспрам θ=0) остаје као тест-асертација:
као детектор није поуздана јер хвата само непаран број промена гране.

**ОДЛУКА — пуна скална инваријантност фитнеса.** Генерисана путања се пре Chamfer-a
нормализује истом функцијом као циљна крива (`curve.normalize`). Фитнес мери искључиво облик.
Геном се током претраге не дира — чвор 0 остаје закуцан у (0,0), димензионалност остаје
`2n−2`. На крају покретања најбоља сличносна трансформација се примењује на координате
најбољег генома, па снимљени механизам стварно исцртава циљну криву на њеном месту и у
њеној величини (сличносна трансформација координата даје идентично трансформисану путању —
провера, одступање 1.3e-15).

Мерено (елипса, буџет 12 000, популација 50, заједничка мера = Chamfer после оптималне
сличносне трансформације): без инваријантности 2.02e-02, само транслациона 4.65e-04 (43×),
транслација+скала 1.26e-05 (1600×). Медијана преко 4 seed-а: 1100×. Претрага по ротацији не
доноси ништа (ротацију механизам постиже сам) и не уводи се.

Инваријантност не чини фитнес попустљивијим него ужим: савршена елипса померена за (2,−1)
пада са 4.623 на 0, али круг радијуса 1 на правом месту добија 0.2155 под сва три режима.

Цена коју треба знати: под пуном скалном инваријантношћу механизам испадне гломазнији од
криве коју црта (највећа полуга / полупречник путање = 6.73, наспрам 1.06 код контроле).
Отуда одлука о компактности испод.

**ОДЛУКА — градирана казна се НЕ уводи.** Остаје равна `PENALTY = 1e9` за сваку невалидну
јединку, без обзира колико је обртаја прешла. Разлог одбијања: „докле је стигао обртај" није
својство механизма него пара (механизам, паркирани угао ручице) — мерено, за исти механизам
вредност варира од 0.00 до 0.78 зависно од почетног офсета. Замена (мера изводљивих углова)
је такође одбијена: градирана казна сама по себи није помогла (0.6×, унутар шума).

**ОДЛУКА — кеш оцене елите унутар истог N.** Јединка која се преноси непромењена и чија је
оцена већ позната на истом N не троши нов позив буџета. **На свакој промени N кеш се
поништава и цела популација се оцењује изнова**, укључујући и елиту — Chamfer са различитих
N није упоредив. Мерено: оцене непромењене елите су бит-идентичне кад се N не промени; у
покретању од 500 генерација то је 9 940 од 50 000 позива, дакле 19.9% буџета.

**ОДЛУКА — подузорковање циљне криве на N.** `curve.resample` се прикључује у `fitness.evaluate`
— за дато N циљна крива се подузоркује на истих N тачака (за N=180 свака 4. тачка). Функција
је постојала од задатка 2 али никад није била прикључена; циљна крива је увек имала свих 720
тачака. KD-дрво се гради једном по нивоу N, не по евалуацији. Ефекат је мали (око 2% на N=90)
и у истом смеру.

**ОДЛУКА — праг угла преноса 10°.** `Config.min_transmission_angle_deg` иде са 5.0 на 10.0.
Ревизија после анализе расподеле углова; следећи разуман корак је 20°. Мерено колико праг
стеже (удео тополошки валидних које заврше пун обртај): 5° → 80.7%, 10° → 73.6%, 20° → 56.8%,
40° → 14.8%. Литературних 40° за четворополужја би побило 85% популације.

**НАЛАЗ (04.09.) — минимални угао преноса се групише уз праг на тежим кривама; праг остаје
10°.** На петнаест покретања нивоа 1 (§19): `superellipse` seed3 = 10.0°, `cassini` seed2 =
10.6°, `superellipse` seed2 = 11.1°, `limacon` seed3 = 11.1°, `egg` seed1 = 11.2° — седам од
петнаест покретања у првом степену изнад прага. Ово је налаз, не проблем: испод 10° механизми
пролазе превише близу мртве тачке — нумерички решиви, физички неизводљиви. Праг није
ограничење претраге које треба ослободити него ограничење стварности које треба поштовати, па
се вредност не мења. Отворено питање 6.2 (ревизија прага) остаје отворено, али неургентно —
нема грудвања поред самог прага у смислу да би претрага систематски покушавала да га пробије.

**ОДЛУКА — компактност улази само у лог.** `GenerationRecord` добија поље са односом
највећа полуга / полупречник путање најбоље јединке. НЕ улази у оцену док се не види
расподела кроз неколико покретања. Chamfer остаје једина мера квалитета поклапања.
**РЕВИДИРАНО 03.09. — в. секцију 18: компактност улази у оцену као тврда граница 5.0.**

**УПОРЕДИВОСТ:** покретања од 02.09. нису упоредива ни са једним ранијим логом — мења се и
симулатор и фитнес.

## 18. Ревизија §17: граница гломазности, затворено поравнање, прослеђивање config-а (закључано 03.09.)

Три измене над §17, све изведене из мерења после прве имплементације.

**ОДЛУКА — гломазност улази у оцену као тврда граница 5.0** (ревидира §17 „компактност улази
само у лог"). `Config.max_link_to_radius_ratio = 5.0`; јединка чији однос највећа полуга /
полупречник путање пређе границу добија `PENALTY`. Провера иде после `center_and_radius`, пре
`chamfer` — одбачена јединка не плаћа изградњу KD-дрвета. Тврда граница, НЕ члан у фитнесу:
Chamfer остаје једина мера квалитета поклапања, гломазност само одсеца неупотребљив део
простора решења.

Разлог: под пуном скалном инваријантношћу фитнес не види величину механизма у односу на криву
коју црта, па претрага одлази у гломазна решења — мерено 6.73× и 26.78× на буџету од 12 000
позива. Механизам 27× већи од своје криве није употребљив ма колико му Chamfer био низак.

Мерено (`--quick`, елипса, 3 seed-а, са исправно прослеђеним config-ом): граница 10 → медијана
Chamfer 3.93e-04, односи 2.69/8.80/5.98, углови преноса 30°/14°/11°; граница 5 → медијана
1.35e-04, односи 4.64/4.84/4.24, углови преноса 40°/29°/31°. Граница 5 није скупља, а решења
остају даље од мртве тачке. Почетну популацију не гуши: 73–82% решивих јединки већ је испод 5.

**Затвара отворено питање 6.1** — одговор је тврда горња граница, не члан у фитнесу.

**ОДЛУКА — поравнање путање са циљем у затвореном облику.** `curve.place_on_target` замењује
`fitness.fit_similarity_transform` (Nelder-Mead), која се брише. Фитнес пореди `normalize(path)`
са већ нормализованом циљном кривом, а `normalize` не ротира — ГА је оријентацију већ морао сам
да погоди да би добио низак фитнес. Поравнању остају транслација и скала, обе из
`center_and_radius`; ротација је нула по конструкцији.

Разлог одбацивања оптимизатора: из почетне тачке код идентитета не стиже до оптимума кад је
путања далеко или друге величине — што је постало норма чим је фитнес престао да ограничава
позу. Мерено: прогон од 12 000 позива достигао 1.13e-05, поравнање нашло 1.62e-03 (140× горе);
на контролисаним случајевима промашај до 4.52e-01. Затворен образац даје резултат ТАЧНО једнак
`evaluate`-у (проверено на три генома: разлика 6.7e-18, 1.3e-18, 2.1e-16).

**ОДЛУКА — `config` се мора прослеђивати кроз цео ланац.** `baseline.evolve` → `evaluate` →
`simulate`, и `run.py` → `visualization.tracer_path` → `simulate`.

Грешка нађена мерењем: `evolve` је звао `evaluate(...)` без `config`, а `evaluate` је звао
`simulate(...)` без `config`, па су и граница гломазности и праг угла преноса тихо долазили из
`DEFAULT_CONFIG` без обзира шта је покретање проследило. Доказ: два `--quick` прогона са
границама 5 и 10 дала су бит-идентичне резултате.

**Обрасац вредан памћења: подразумевана вредност параметра уме да сакрије прекинут ланац.**
Позив ради, тестови пролазе, а конфигурација се тихо игнорише. Ухваћено само зато што је мерено
да ли измена границе уопште мења ишта. Регресиони тест: исти seed са различитим границама мора
дати различит резултат И различит `invalid_count` у нултој генерацији (мерено 19/30 наспрам 15/30).

## 19. Криве нивоа 1 и статус буџета (закључано 03.09., РЕВИДИРАНО 04.09.)

**ОДЛУКА — ниво 1 се проширује са две на шест кривих.** Уз `circle` и `ellipse` додају се
`egg`, `limacon`, `cassini`, `superellipse`. Ревидира §11 и README 3.4. (03.09.: додата је и
`figure8`, седам кривих укупно — избачена 04.09., в. одлуку испод.)

Разлог: под пуном скалном инваријантношћу (§17) кружна путања БИЛО КОГ полупречника савршено
погађа круг. Мерено на шест пуних прогона: круг завршава на 2.17e-12 до 2.23e-08, четири до
осам редова величине испод елипсе (2.01e-05). Круг више не мери способност метода него
тривијалност задатка, па је ниво 1 фактички имао само један прави тест. Калибрација ГА
хиперпараметара (следећи корак, §8 best-effort) на једној кривој значила би калибрацију
**на ту криву**.

Свака нова крива додаје ДРУГУ врсту тежине, не само „више исто" (мерено на густом
параметарском узорку):

| крива | шта додаје | мерено |
|---|---|---|
| `egg` | руши двоструку симетрију елипсе — једна оса уместо две | конвексна свуда |
| `limacon` | прва промена знака кривине | конкавна на 11% обима |
| `cassini` | изражен струк, два режња, јака неконвексност | конкавна на 39% обима |
| `superellipse` | равне странице, кривина у четири области | конвексна; најближа словима |

**Ниједна нема шпиц.** Шпиц захтева да трагач тренутно стане — сингуларна конфигурација коју
праг угла преноса ионако одбија, па кардиоида и слични облици не би били тешки него
неизводљиви. Мерено: минимална брзина трагача по параметру је 0.30–0.53 просека код свих
четири.

Генератор: `tools/make_curves_level1.py` (720 тачака, `x,y`, шест децимала, узорковање
равномерно по дужини лука — `fitness.evaluate` циљну криву ионако подузоркује преко
`curve.resample` по дужини лука). Преглед: `docs/krive_nivo1.png`.

**Ниво 1 се шири, а не ниво 2, зато што је овде извор ФОРМУЛА, не цртеж** — питање 4.6
(извор тачака за слова и Јансенову криву) остаје отворено и ово га не дира. Слова која сами
нацртамо рушила би упоредивост са LInK литературом, што је цела поента нивоа 2.

**ОДЛУКА (04.09.) — `figure8` избачена; критеријум за криву нивоа 1: затворена и без
самопресека, конвексност се НЕ тражи.** `figure8` (самопресецајућа осмица) је уведена
03.09. као пета додата крива, мерено најтежа од пет — али мерење петнаест покретања нивоа 1
показује да разлика није степен тежине него врста проблема: `figure8` је на сва три seed-а
стала на 2.4e-02 до 3.0e-02, ред величине изнад следеће најтеже криве (`superellipse`,
5.6e-03 до 7.0e-03). Разлог: самопресек тражи да трагач двапут прође исту тачку равни у
различитим фазама обртаја, што од механизма тражи структуру коју четворополужје са спрежном
тачком уопште не мора да поседује.

Критеријум конвексности би искључио и Јансенову криву (циљ нивоа 3, §11) — мерено на 720
тачака: 0 самопресека, 472 од 720 тачака на конвексном омотачу (тј. НИЈЕ конвексна), површина
криве/омотача 0.939, макс. дубина удубљења 2.43 (10.8% висине криве). Критеријум одсуства
самопресека Јансенову криву задржава, критеријум конвексности би је искључио — отуда одсуство
самопресека, не конвексност. Ниво 1 после овога: `circle`, `ellipse`, `egg`, `limacon`,
`cassini`, `superellipse` — шест кривих (потврђено §11).

**Не дирати `path_health`.** 32 „скока" забележена на `figure8` seed3 нису била стварна
промена гране (промена гране 0, дрифт после 2π 7.8e-16) него неравномерна брзина трагача на
кривој са самопресеком — артефакт криве, не грешка детектора. Брисањем `figure8` случај
нестаје сам, без измене детектора.

**ОДЛУКА — круг се у раду наводи као дегенерисан тест, не као успех.** Његов резултат од
1e-12 под скалном инваријантношћу не мери метод. Не прећутати га; навести уз објашњење зашто.

**ОДЛУКА — плато-критеријум остаје какав јесте; број потрошених позива симулатора се УВЕК
извештава уз коначну грешку.** Рано заустављање се прихвата као легитимна конвергенција, не
као пропуштен буџет.

Разлог: од шест пуних прогона пет је стало на 24–42% буџета. Прва метрика из §8 („коначна
Chamfer грешка при истом буџету") претпоставља да буџет везује — не везује. Уместо да се
плато лабави док не веже, прихвата се да прогон конвергира и извештава се пар
**(коначна грешка, потрошени позиви)**. То спаја прву и другу метрику из §8 у једну обавезну
пријаву. Мора бити тако формулисано и у раду: поређење baseline и bilevel даје две бројке по
прогону, не једну.

**Затвара отворена питања 6.4 и 6.5.**

## 20. Снимци постављени на циљну криву; `--max-link-ratio` параметар покретања (закључано 04.09.)

Две измене после анализе петнаест покретања нивоа 1 (§19).

**ОДЛУКА — `visualization.snapshot` црта постављен механизам, не сирове координате.** Пуна
скална инваријантност фитнеса (02.09., §17) пореди путању тек ПОСЛЕ нормализације, па сирова
путања у координатама механизма и нормализована циљна крива леже на различитим местима и у
различитим размерама — слика је деловала лоше и кад је јединка добра. `snapshot` сад примењује
исту сличносну трансформацију коју `run.py` примењује на крају покретања: `curve.place_on_target`
на путањи, `curve.apply_similarity_transform` на координатама и на путањи (еквивалентно,
README 1.5). Ако је путања дегенерисана (радијус ~0) или `tracer_path` врати `None`, цртa се
некоригована путања уз напомену на слици — цртање и даље не сме да обори тренинг.

**ОДЛУКА — `snapshot` ради на копији генома.** `progress.ProgressReporter._snapshot` прима
`log.best_genome` — објекат који опстаје кроз генерације (враћа се и на крају као резултат
`baseline.evolve`-а). Измена координата на месту би тихо покварила тај резултат, не само тренутни
снимак: сваки следећи позив `_snapshot` (или крајња обрада у `run.py`) радио би над већ
трансформисаним координатама, удвостручавајући трансформацију без упозорења. `snapshot` зато
прво прави дубоку копију (`topology.copy()` + `coords.copy()`) и мења само копију. Регресиони
тест: `tests/test_visualization.py::test_snapshot_does_not_mutate_genome_coords`.

**ОДЛУКА — `config` се прослеђује до краја ланца цртања.** `tracer_path` (затворено 03.09., §18)
већ прима `config`; сада га прима и `snapshot`, `ProgressReporter.__init__` га чува
(`self.config`), `run.py` му га проследи при конструкцији репортера. Исти образац који је
затворен за `evolve` → `evaluate` → `simulate` (§18), продужен на путању цртања.

**ОДЛУКА — `Config.max_link_to_radius_ratio` изведена у параметар командне линије.**
`run.py run --max-link-ratio FLOAT`, подразумевано `None` → узима се вредност из профила (5.0,
§18). `Config` је `frozen`, вредност улази преко `dataclasses.replace`. Мотивација: сва три
покретања на `egg` стала су на 4.97–4.99, `superellipse` seed3 на 4.95, `cassini` seed3 на
4.88 — граница 5.0 је постала зид, не ограничење; није познато да ли то кошта тачност. Уместо
нагађања, вредност се изводи у CLI да се покрене контролисано поређење (§21, кад буде мерено).
Вредност улази у `command.txt` (репродуктивност — исти образац као `--budget`/`--population`,
увек уписана резолвована вредност, не само кад је експлицитно задата) и у заглавље
`ProgressReporter.start()` (ред „гломазност ≤"), да се из самог излаза покретања види под којим
ограничењем је рађено.

## 23. Предлог: H1 мерење од 05.09. није поуздано на пуном профилу; дијагностика на фиксном N даје охрабрујући правац (05.09., ЧЕКА ПОТВРДУ)

Пун опис, табеле и рачун: `docs/NALAZ_05_09_bilevel.md`. Ово је ПРЕДЛОГ читања налаза, не
закључак — изричито означено по узору на §21.

**НАЛАЗ — главна матрица (3 seed-а × 6 кривих × 2 метода, пуни профил, динамички N) НИЈЕ
употребљива за H1.** Свих 18 bilevel покретања остало је заглављено на N=90 од прве до
последње генерације (никад напредовало на 180/360/720), док је baseline редовно стизао до
N=720. Узрок: плато-прозори за раст резолуције и заустављање (`plateau_window_grow=15`,
`plateau_window_stop=30`) броје по ГЕНЕРАЦИЈИ спољашњег ГА, а bilevel-ова генерација кошта
ред величине више позива него baseline-ова (K×λ по топологији) — цео буџет од 50 000
потроши се за 16–20 спољашњих генерација, испод сваког прозора. Chamfer на различитим N
није упоредив (§17) — медијане из те матрице НИСУ мера тачности метода, него артефакт
неусклађене инфраструктуре. Ново отворено питање: `docs/OPEN_QUESTIONS.md` §6.6.

**НАЛАЗ — дијагностика на фиксном `n_schedule=(720,)` за оба метода (један seed, свих шест
кривих) даје доследан правац у корист bilevel-a.** Bilevel нижи коначни Chamfer на 4 од 5
нетривијалних кривих (ellipse 0.37×, egg 0.19×, cassini 0.31×, limacon 0.34× — све јасно
испод шум-опсега 0.6–1.2×), практично изједначен на superellipse (0.65×, на ивици тог
опсега). Провера криве конвергенције (не само коначне вредности) показује да bilevel
СТВАРНО користи вишак буџета продуктивно на већини кривих (и даље опада до последње
генерације), не да „стоји" на резултату.

**ПРЕДЛОГ (чека потврду) — три ствари, изричито одвојене:**

1. **H1 се НЕ сматра ни потврђеним ни обореним овом ноћи.** Главна матрица је методолошки
   неисправна (различите N), дијагностика је охрабрујућа али на једном seed-у по кривој —
   премало за закључак какав овај пројекат рачуна поузданим (§21 стандард: три seed-а је
   већ мали узорак, један је мањи).
2. **Пре поновног мерења треба решити §6.6** (плато-прозори за bilevel) — или посебни,
   мањи прозори за спољашњи ГА, или мерење плата по ПОЗИВИМА уместо по ГЕНЕРАЦИЈИ,
   заједничко за оба метода. Ово НИЈЕ одлучено — избор архитектуре, не калибрациони број,
   тражи Николину одлуку пре имплементације (CLAUDE §3).
3. **Кад §6.6 буде решено, понови главну матрицу (три seed-а, шест кривих) под тим
   решењем** — тек тада поређење медијана значи оно што §8 тражи.

**Оно што ОВА одлука НЕ мења:** ниједан подразумевани параметар у `config.py`
(`n_schedule`, `plateau_window_grow`, `plateau_window_stop` остају какви јесу — дијагностика
је рађена преко `dataclasses.replace`, ефемерно, исти образац као §21/`--max-link-ratio`
варијације). `bilevel.py`/`geometry_vector.py` имплементација (§22) остаје — проблем је у
заједничкој `experiment.py` инфраструктури плато-детекције, не у самом bilevel методу.

## 22. Bilevel: параметризација, мртви чворови, спољашња шема (закључано 04.09.)

Донето у чет-сесији 04.09., затвара отворено питање 2.1 у целости (warm-start половина
која се тицала bilevel-a). Извршни облик: `PROMPT_BILEVEL.md` целина А. Ниједна од ових
одлука не мења baseline — то доказује регресиони тест (в. целина Д истог промпта, бит-
идентичан резултат `baseline.evolve` пре и после ове имплементације).

**ОДЛУКА — топологија и геометрија се цепају по секвенци склапања, не по скупу ивица.**
Спољашњи ГА носи скелет секвенце `TopologySkeleton = {n_nodes, genes: [(a_k, b_k, s_k)]}`
— `SequenceGene` без `rho_a`/`rho_b`. Знак гране `s` је дискретан и по §17 (закуцана
грана) својство склопа, не последица тренутне геометрије — зато припада топологији, не
континуалном вектору. Унутрашњи ЦМА-ЕС носи вектор `x = [q1x,q1y,q2x,q2y,ρ_a3,ρ_b3,...]`
(чвор 0 закуцан у (0,0)), дужине `2n−2` кад нема мртвог терета — иста димензионалност
коју README 1.2 већ прописује, само у бази `(q1,q2,ρ)` уместо сирових координата свих
чворова.

Разлог избора баш ове базе: из координата се грана изводи (знак стране праве `a→b` на
којој чвор лежи). ЦМА-ЕС који слободно помера координате може ту праву прећи усред
претраге, па се `s` тихо превали и фитнес скочи — иста класа проблема коју је §17
уклонила из симулатора. У бази `(q1,q2,ρ)` знак је фиксан ген топологије, па је
пресликавање `x → механизам` непрекидно свуда осим на самом рубу изводљивости (кругови
престану да се секу → `from_sequence` врати `None` → казна).

Напомена: угао ручице у θ=0 (позиција `q2`) НИЈЕ сувишна димензија у овој бази. Chamfer
јесте инваријантан на фазу обиласка, али `ρ` су односи према размаку ослонаца **у θ=0**,
па померање `q2` мења стварне дужине полуга, дакле и сам механизам.

**ОДЛУКА — мртви чворови не заузимају димензије ЦМА-ЕС вектора.** Активне су само
позиције из предачког стабла трагача; `ρ` мртвих чворова се замрзавају на затеченим
вредностима и враћају при реконструкцији. Језгро (`q1`, `q2`) је увек активно. Разлог:
мртав чвор по дефиницији не утиче на путању (README 2.3), па би његове две димензије биле
равне правце у простору претраге, а трошак ЦМА-ЕС-а расте са квадратом димензије. Одлука
од 30.08. („мртви чворови се не кресају током претраге") остаје нетакнута — они и даље
постоје у геному као материјал за каснији потез начина А, само их унутрашњи ниво не
оптимизује.

**ОДЛУКА — спољашњи ниво је генерацијски, са живим ЦМА-ЕС стањем по топологији.** Свака
топологија у популацији носи свој `cma.CMAEvolutionStrategy` објекат који се наставља
кроз генерације, не рестартује. Елита у следећој генерацији добија још K итерација уместо
да се бесплатно препише. Природан облик „динамичког K" (README 2.4) на нивоу целог
покретања.

**ОДЛУКА — warm-start = наслеђена средина + сопствена почетна σ за нове димензије.** Дете
наслеђује родитељеву најбољу тачку `x*` као почетну средину; димензије које постоје и код
родитеља наслеђују и родитељеву тренутну ширину по координати (`sigma · stds`, дијагонала),
а нове две димензије добијају `config.cma_sigma0_new`. Пуна ковaријациона матрица се НЕ
пресађује (само дијагонала) — пренос ван-дијагоналних чланова кроз промену димензије није
дефинисан једнозначно и не вреди ризика.

**ОДЛУКА — јединица трошка остаје иста: један кандидат = један позив буџета.** Свака тачка
коју ЦМА-ЕС узоркује троши тачно један позив, укључујући и оне које падну на
реконструкцији (`from_sequence` врати `None`, пре `simulate`-а) — исто правило које
baseline већ има за невалидне јединке (`fitness.evaluate` инкрементира бројач на свакој
грани). Без овога bilevel би добијао бесплатне промашаје и поређење H1 би било неисправно
у нашу корист.

**ОДЛУКА — невалидна тополошка мутација кошта један позив, не цео ЦМА-ЕС ран.** Дете чији
скелет падне на `validation.validate` добија `PENALTY`, наплаћује се један позив и не
добија ЦМА-ЕС објекат; умире при следећој селекцији. Правило „мутација се не понавља до
валидне" (README 2.3) је поштовано — јединка остаје у популацији са казном; додаје се само
то да се на мртву топологију не троши `λ·K` позива.

**ОДЛУКА — у bilevel-у нема координатне мутације ни укрштања.** Геометрију решава
искључиво унутрашњи ЦМА-ЕС (то је цела поента H1), а по H2 (README 3.5) спољашњи ГА
користи само само-мутацију. `p_coord` се у bilevel профилу игнорише; тополошки оператори
су исти (`add_node` А и Б, `delete_node`) са истим вероватноћама.

**НАПОМЕНА:** ниједна од ових одлука не мења baseline. `pantograph/baseline.py` остаје
нетакнут; `pantograph/genome.py`, `simulator.py`, `validation.py`, `fitness.py`, `curve.py`
задржавају семантику. Регресиони тест то доказује бит-идентичним резултатом.

## 24. Границе ρ и РНГ токови за унутрашњи ЦМА-ЕС (закључано 05.09.)

Три одлуке донете у чет-сесији 05.09., извршни облик: `PROMPT_RNG.md`. Мењају bilevel
бројеве (поништавају резултате §23), не мењају baseline — доказано регресионим тестом
(в. целина Г истог промпта).

**ОДЛУКА — границе ρ у ЦМА-ЕС вектору се проширују, а clip почетне тачке уклања.**
`config.cma_rho_lower` иде са 0.05 на 0.01, `config.cma_rho_upper` са 20.0 на 100.0 —
довољно широко да их законити оператори не могу пробити. `clip` почетне тачке, уведен
05.09. у `_construct_cma_es` као решење-без-одлагања (в. §22 округли докстринг тог тренутка),
се уклања и НЕ замењује другим тихим прилагођавањем. Разлог: clip је тихо мењао геометрију
детета у односу на ону коју је оператор произвео, чиме је нарушавао оправдање warm-start-а
(„дете креће близу родитеља"). Уска граница није радила посао који већ не ради тврда граница
гломазности (`max_link_to_radius_ratio = 5.0`, §18) — други појас преко истих панталона.
Уместо да се мери колико се често окида, уклања се узрок. ЦМА-ЕС и даље МОРА имати
декларисане границе (конструктор захтева почетну тачку унутар њих) — оне више нису активно
ограничење, само декларација. Дете чији ρ ипак испадне ван (нових, ширих) граница се
третира као невалидна мутација (§22 А6 продужено на нови узрок): трошi тачно један позив,
не добија ЦМА-ЕС објекат, не поправља се тихо. Бројач `RunLog.rho_out_of_bounds` бележи
да ли се то икада догодило.

**ОДЛУКА — H1 мерење иде у засебан режим поређења.** Фиксно `N=720` за оба метода, исти
буџет за оба (полазно 100 000 позива), без раног заустављања на плато; извештава се цела
крива грешка-по-позивима, не једна коначна бројка. Разлог: §23 је показало да плато-прозори
подешени за baseline-ову грануларност генерације не раде за bilevel (§6.6) — уместо да се
поправља заједничка инфраструктура плато-детекције пре сваког мерења H1, за само мерење H1
се та инфраструктура заобилази у потпуности. §18 (буџет 50 000, растући N) остаје
подразумевани профил за развој и дијагностику; ово је ДРУГИ, засебан профил само за
H1 поређење. Имплементација овог режима НИЈЕ део `PROMPT_RNG.md` — иде у засебно упутство.

**ОДЛУКА — унутрашњи ЦМА-ЕС добија сопствени `randn` уместо ослањања на snapshot legacy
стања, и позиционо семе уместо редног.**

*Предаја узорака:* `cma` (верзија 4.4.4) вуче нормале искључиво из `self.randn` у
`sampler.py`, не из приватног генератора — упркос томе што прима опцију `seed`. Библиотека
то сама документује (`evolution_strategy.py:1101`): `seed` се користи само док је
`opts['randn'] is np.random.randn`. Опција се сад поставља на
`lambda lam, N: record.rng.standard_normal((lam, N))` (облик тачно `(lam, N)`, потврђено у
`sampler.py`), а `opts['seed'] = np.nan` гаси упозорење библиотеке (`utils.is_nan` враћа
`True`, цео `if`-блок који и упозорава и позива `np.random.seed` се прескаче — потврђено
читањем извора, не претпоставком). Последица: `TopologyRecord.rng_state` и `_ask_isolated`
се бришу заједно са сваким снимањем/враћањем `np.random.get_state()/set_state()` у
`_construct_cma_es` — не остају као резервна путања. Snapshot штити само путеве које смо
прегледали; свака непрегледана путања остаје тиха рупа, а уклањањем зависности рупа
престаје да постоји као категорија. Провера изворног кода cma 4.4.4 (05.09.): узорковање
иде искључиво кроз `self.randn`, `boundary_handler.py` је детерминистичан, остале појаве
`np.random` у пакету су doctest-ови или опције које не користимо.

*Извор семена:* `seed = int(rng_cma.integers(...))` по реду стварања записа значи да број
створених ЦМА-ЕС објеката (спољашња популација, третман невалидне деце, `k_max`) помера
токове СВИХ наредних топологија — тачно она грешка коју је одлука о четири тока (30.08.)
спречавала, само на дубљем нивоу. Замена: семе зависи од ПОЗИЦИЈЕ, не од историје —
`cma_rng(main_seed, generation, slot) = np.random.default_rng([main_seed, KLJUC_CMA,
generation, slot])`, `KLJUC_CMA = 5` константа. На почетку сваке спољашње генерације,
пре `inner_cmaes`, сваки запис добија `record.rng = cma_rng(main_seed, generation, slot)`
где је `slot` његово место у спољашњој популацији те генерације — потрошено у генерацији
*g* зависи само од `(seed, g, slot)`, не од броја објеката створених пре њега. Запис живи
кроз генерације (§22, живо ЦМА-ЕС стање) непромењено — мења се само одакле му долазе
нормале у датој генерацији. Последица: пети спawn-овани ток `rng_cma` постаје непотребан,
`spawn_rng_streams` се враћа на четири тока, опциони `n_streams` се уклања.

**ОГРАНИЧЕЊЕ (не преувеличавати):** позиционо семе НЕ даје пуну упоредивост кроз верзије
кода — која топологија седи на ком месту зависи од селекције, дакле од фитнеса, дакле се и
то мења између верзија. Уклања се ТИХА СПРЕГА (промена нечег концептуално неповезаног
помера све токове), не постиже се гаранција поновљивости кроз измене.
