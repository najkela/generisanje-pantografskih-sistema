## А. Одлуке које овај задатак уводи — прво их упиши, па онда кодирај

Ово су одлуке донете у чет-сесији 04.09. и оне затварају отворено питање 2.1 у целости.
Упиши их у `docs/DECISIONS.md` као **`## 22. Bilevel: параметризација, мртви чворови, спољашња
шема (закључано 04.09.)`**, у постојећем стилу (`**ОДЛУКА — назив:** образложење`), и ажурирај
`docs/OPEN_QUESTIONS.md` (2.1 → ЗАТВОРЕНО 04.09.) и табелу у `CLAUDE.md` §8.

**А1 — ОДЛУКА: топологија и геометрија се цепају по секвенци склапања, не по скупу ивица.**
Спољашњи ГА носи *скелет секвенце*:

```
TopologySkeleton = { n_nodes: int, genes: [(a_k, b_k, s_k) за k = 3 … n−1] }
```

Дакле `SequenceGene` без `rho_a`/`rho_b`. Знак гране `s` је **дискретан** и по одлуци §17
(закуцана грана) он је својство склопа, не последица тренутне геометрије — зато припада
топологији, а не континуалном вектору.

Унутрашњи ЦМА-ЕС носи вектор

```
x = [ q1x, q1y, q2x, q2y, rho_a3, rho_b3, rho_a4, rho_b4, … ]
```

(чвор 0 је закуцан у (0,0), README 1.3), дужине `4 + 2·(број гена) = 2n − 2` кад нема мртвог
терета — иста димензионалност коју README 1.2 већ прописује, само у другој бази.

*Зашто не сирове координате.* Из координата се грана изводи (`to_sequence` рачуна `s` по томе
са које стране праве `a→b` чвор лежи). ЦМА-ЕС који помера координате може ту праву да пређе
усред претраге, па се `s` тихо превали и фитнес скочи — иста класа проблема коју је §17
уклонила из симулатора. У бази `(q1, q2, ρ)` знак је фиксан ген топологије, па је пресликавање
`x → механизам` непрекидно свуда осим на самом рубу изводљивости (кругови престану да се секу
→ `from_sequence` врати `None` → казна).

*Напомена коју треба записати:* угао ручице у θ=0 није сувишна димензија у овој бази. Chamfer
јесте инваријантан на фазу обиласка, али `ρ` су односи према размаку ослонаца **у θ=0**, па
померање `q2` мења стварне дужине полуга, дакле и механизам.

**А2 — ОДЛУКА: мртви чворови не заузимају димензије ЦМА-ЕС вектора.** Активне су само
позиције из предачког стабла трагача; `ρ` мртвих чворова се замрзавају на затеченим
вредностима и враћају при реконструкцији. Језгро (`q1`, `q2`) је увек активно.

*Зашто:* мртав чвор по дефиницији не утиче на путању (README 2.3), па би његове две димензије
биле равне правце у простору претраге, а трошак ЦМА-ЕС-а расте са квадратом димензије. Одлука
од 30.08. („мртви чворови се не кресају током претраге") остаје нетакнута — они и даље постоје
у геному као материјал за каснији потез начина А, само их унутрашњи ниво не оптимизује.

**А3 — ОДЛУКА: спољашњи ниво је генерацијски, са живим ЦМА-ЕС стањем по топологији.** Свака
топологија у популацији носи свој `cma.CMAEvolutionStrategy` објекат који се **наставља** кроз
генерације, не рестартује. Елита у следећој генерацији добија још K итерација уместо да се
бесплатно препише. Ово је природан облик „динамичког K" (README 2.4) на нивоу целог покретања.

**А4 — ОДЛУКА: warm-start = наслеђена средина + сопствена почетна σ за нове димензије.**
Дете наслеђује родитељеву најбољу тачку `x*` као почетну средину; димензије које постоје и код
родитеља наслеђују и родитељеву тренутну ширину по координати (`sigma · stds`, дијагонала), а
нове две димензије добијају `config.cma_sigma0_new`. Пуна ковaријациона матрица се **не**
пресађује (само дијагонала) — пренос ван-дијагоналних чланова кроз промену димензије није
дефинисан једнозначно и не вреди ризика.

**А5 — ОДЛУКА: јединица трошка остаје иста — један кандидат = један позив буџета.** Свака
тачка коју ЦМА-ЕС узоркује троши тачно један позив, **укључујући и оне које падну на
реконструкцији** (`from_sequence` врати `None`, пре `simulate`-а). Исто правило које baseline
већ има за невалидне јединке (`fitness.evaluate` инкрементира бројач на свакој грани). Без
овога bilevel би добијао бесплатне промашаје и поређење H1 би било неисправно у нашу корист.

**А6 — ОДЛУКА: невалидна тополошка мутација кошта један позив, не цео ЦМА-ЕС ран.** Дете чији
скелет падне на `validation.validate` добија `PENALTY`, наплаћује се један позив и **не добија
ЦМА-ЕС објекат**; умире при следећој селекцији. Правило „мутација се не понавља до валидне"
(README 2.3) је поштовано — јединка остаје у популацији са казном. Оно што се овде додаје је
само то да се на мртву топологију не троши `λ·K` позива.

**А7 — ОДЛУКА: у bilevel-у нема координатне мутације ни укрштања.** Геометрију решава
искључиво унутрашњи ЦМА-ЕС (то је цела поента H1), а по H2 (README 3.5) спољашњи ГА користи
само само-мутацију. `p_coord` се у bilevel профилу игнорише; тополошки оператори су исти
(`add_node` А и Б, `delete_node`) са истим вероватноћама.

Напиши уз §22 и реченицу да ове одлуке **не мењају ништа у baseline-у** — то целина Д и
доказује.

**Дневник рада:** припреми нацрт уноса у `docs/DNEVNIK_NACRT_05_09.md` (структура из
CLAUDE.md §9: `## Дискусија`, `## Одлуке`, `## Отворена питања`, `## Наредни кораци`).
**Не пиши у Notion** — за то треба изричита дозвола коју ноћас нема ко да да.

## Б. `pantograph/geometry_vector.py` — пресликавање секвенца ↔ вектор

Нов модул. Не дирај `genome.py` осим ако мораш да додаш `TopologySkeleton` — ако додајеш,
додај га у `genome.py` поред `SequenceGene`/`Sequence`, јер тамо већ живе сродне структуре.

Потребно:

- `@dataclass TopologySkeleton` са `n_nodes: int` и `genes: list[tuple[int, int, int]]`
  (`a`, `b`, `s`), уз `copy()`.
- `skeleton_of(seq: Sequence) -> TopologySkeleton` — одбаци `ρ`.
- `active_positions(skeleton) -> list[int]` — позиције `k ≥ 3` које су у предачком стаблу
  трагача. Предачко стабло рачунај из самог скелета (`a`, `b` показују уназад, инваријанта
  редоследа §16), не преко `prune_dead_nodes`.
- `to_x(seq, active) -> np.ndarray` и
  `to_sequence_from_x(x, skeleton, frozen_rho, active) -> Sequence`, где је `frozen_rho`
  речник `позиција → (rho_a, rho_b)` за мртве чворове.
- `evaluate_vector(x, skeleton, frozen_rho, active, target, n, counter, config) -> float` —
  једина капија ка фитнесу: склопи секвенцу → `genome.from_sequence` → ако је `None`,
  `counter.increment()` и врати `fitness.PENALTY` (одлука А5) → иначе
  `fitness.evaluate(Genome(topology, coords), target, n, counter=counter, config=config)`.
  Тачно **један** инкремент бројача на свакој грани, без изузетка.

Тестови (`tests/test_geometry_vector.py`):

1. Round-trip: `random_initial_genome` → `to_sequence` → `to_x` → назад → координате се
   поклапају на `1e-12`.
2. Димензија је `2n−2` кад мртвог терета нема.
3. Геном са мртвим чвором (направи га `add_node` начином Б): димензија је за 2 мања, а
   `evaluate_vector` даје **исти број** као `fitness.evaluate` над оригиналним геномом —
   мртав чвор не мења путању.
4. Бројач: `k` позива `evaluate_vector` увек даје `counter.count == k`, и за валидне и за
   намерно поломљене векторе (нпр. `rho` тако мали да пресека нема).

## В. `pantograph/bilevel.py` — унутрашњи и спољашњи ниво

Постојеће заглавље и потписи су скелет са `NotImplementedError`. Потписе смеш да прошириш
(CLAUDE.md §7: не мењај их без договора — овај промпт је договор), али задржи имена
`inner_cmaes`, `warm_start`, `outer_ga`.

### В1. `TopologyRecord`

Носи: `skeleton`, `frozen_rho`, `active`, `es` (`cma.CMAEvolutionStrategy | None`), `best_x`,
`best_fitness`, `history` (фитнес по унутрашњој итерацији, за плато), `calls`, `age`.

### В2. `inner_cmaes(record, target, n, budget, config, rng_cma)`

- ЦМА-ЕС из пакета `cma` (инсталиран, 4.4.4). Опције: `seed` изведен из `rng_cma`,
  `popsize` = `config.cma_lambda` (`None` → подразумевано `4 + 3·ln d`), `CMA_stds` (в. В4),
  `bounds`: `ρ` димензије у `[0.05, 20.0]`, димензије језгра неограничене (`None`),
  `verbose: -9`, `verb_log: 0`, `verb_disp: 0` — покретање не сме да штампа ништа своје,
  испис иде искључиво кроз `ProgressReporter`.
- Једна итерација = `es.ask()` → оцени сваког кандидата преко `evaluate_vector` →
  `es.tell(...)`. Свака оцена троши један позив буџета.
- **Динамички K:** стани кад плато траје `config.plateau_window_k` итерација уз праг
  `config.plateau_eps_k` (користи постојећу `experiment.plateau_detected`), или кад се
  достигне `config.k_max`, или кад буџет пресуши. Ако је `config.fixed_k` постављено
  (референтне вредности 5/15/40, H3), плато се игнорише и ради се тачно толико итерација.
- Проверавај буџет **пре сваког `ask()`-а**, и прекини усред оцене популације ако пресуши —
  боље прекинута итерација него прекорачен буџет. Ако је популација прекинута, немој звати
  `tell` са непотпуном листом (`cma` то не прима) — само изађи.
- Ажурирај `record.best_x`/`record.best_fitness` из стварно оцењених кандидата, не из
  `es.result` (који уме да заостане за једну итерацију).

### В3. `warm_start(parent_record, operator_name, index_map, child_seq, config)`

Врати `(x0, stds, sigma0)` за дете:

- `x0` = вектор детета изведен из `child_seq` (то јест из већ мутиране геометрије коју су
  оператори произвели) — не интерполирај ништа сам, оператори су ту одлуку већ носили
  (§15, `add_node` начин А поставља нови чвор на `α·L` од старог трагача).
- `stds`: за сваку димензију детета која има претка у родитељу (по `index_map`), узми
  родитељеву тренутну ширину по тој координати (`parent.es.sigma * parent.es.result.stds[i]`
  или еквивалент из `cma` API-ја који стварно постоји у 4.4.4 — провери, немој да погађаш
  име поља); за нове димензије `config.cma_sigma0_new`.
- `sigma0 = 1.0`, дакле цела скала стоји у `stds`. Тако је почетна ширина по свакој
  координати експлицитна и читљива у логу.

`index_map` праве танки омотачи око оператора у `bilevel.py`, јер само тамо знамо који је
потез примењен:

| потез | пресликавање димензија родитељ → дете |
|---|---|
| `add_node` А | гени `0…m−1` се преносе 1:1; последњи ген је нов |
| `add_node` Б | гени пре места убацивања 1:1; ген на месту убацивања је нов; остали померени за +1 |
| `delete_node` на позицији `p` | ген `p` отпада; гени после њега померени за −1 (зависници којима је пресрачунат `ρ` задржавају родитељеву ширину — то је корак, не вредност) |

Језгро (прве четири димензије) се преноси увек 1:1.

### В4. Почетне ширине (`CMA_stds`)

`[0.6, 0.6]` за `q1`, `[0.3, 0.3]` за `q2`, `[0.15, 0.15]` по гену. Образложење за докстринг:
чвор 1 се иницијализује из `U(−1.5, 1.5)²`, ручица на `U(0.2, 0.8)` од чвора 0, а `ρ` живе око
`U(0.7, 1.3)` — ширине прате те распоне (README 4.1). Ово су **почетне вредности за
калибрацију**, држе се у `config.py`, не расуте по модулу.

### В5. `outer_ga(target, budget, seed, config, reporter=None) -> RunLog`

Огледало `baseline.evolve`-a — исти облик лога, иста плато-логика, исти распоред N, да би
поређење било фер и да би `run.py`, `ProgressReporter` и `plot_error_curve` радили без измена.

- RNG токови: `experiment.spawn_rng_streams` добија опциони параметар `n_streams=4`; bilevel
  зове са `5` и узима пети ток као `rng_cma`. **`SeedSequence.spawn` је детерминистичка по
  редном броју детета, па прва четири тока остају бит-идентична** — то целина Д проверава,
  немој веровати на реч.
- Иницијализација: `config.outer_population` топологија преко `operators.random_initial_genome`
  (исти извор као baseline) → `to_sequence` → скелет + `x0`, свака са свежим ЦМА-ЕС-ом.
- Генерација:
  1. за сваки запис `inner_cmaes` (динамички K);
  2. рангирај по `best_fitness`;
  3. елита `round(0.20·P)` записа преживљава **са својим живим ЦМА-ЕС објектом**;
  4. остатак су деца: родитељ се бира равномерно из горње половине, дете настаје тополошком
     мутацијом (`operators.add_node`/`delete_node`, вероватноће из `config`, форсирања на
     `n_min`/`n_max` иста), па `to_sequence` → скелет + `x0`, па `warm_start`;
  5. невалидно дете → `PENALTY`, један позив, без ЦМА-ЕС-а (одлука А6).
- Распоред N: `experiment.resolution_schedule` над историјом најбољег фитнеса по генерацији.
  **На промену N сваки запис се преоцењује на `best_x`** (један позив по запису) јер Chamfer
  са различитих N није упоредив (§17), и `record.history` се празни.
- Заустављање: буџет, или плато на `n_schedule[-1]` мерен искључиво од уласка у највеће N
  (`max_n_start`, исти образац као у `baseline.evolve` — препиши га, немој измишљати нови).
- `GenerationRecord`: попуни **сва** поља исто као baseline (`working_nodes`,
  `min_transmission_angle_deg`, `path_jump_count`, `path_loop_closure`,
  `link_to_radius_ratio`), рачунато над реконструисаним најбољим геномом, **ван буџета**.
- На крају: `prune_dead_nodes` над најбољим геномом, исто као baseline. Поставу на циљну криву
  (`place_on_target`) ради `run.py`, не `outer_ga`.

## Г. `run.py` — прикључивање

- Уклони `NotImplementedError` за `--method bilevel`; грана позива `bilevel.outer_ga` са истим
  осталим током (репортер, сличносна трансформација, `log.save`, слике, `command.txt`).
- Нови аргументи: `--outer-population` (подразумевано из профила), `--k-max`, `--fixed-k`
  (за H3 референтне 5/15/40, подразумевано `None` → динамички K). Све три улазе у
  `command.txt` резолвоване, исти образац као `--max-link-ratio` (§20).
- `ProgressReporter.start()` већ штампа заглавље — додај ред са `K` режимом и величином
  спољашње популације кад је метод bilevel.
- `--quick` профил мора да ради и за bilevel (мали буџет, мала спољашња популација) — то је
  једини начин да се ноћас брзо провери да петља стоји.

## Д. Обавезна регресија — baseline мора остати бит-идентичан

Ово је капија: **без ње нема мерења.** Разлог је познат овом пројекту — прекинут ланац
`config`-а (§18) нашао се тек мерењем да ли измена уопште мења ишта.

1. **Пре** било какве измене заједничких модула (`experiment.py`, `config.py`, `run.py`)
   покрени и сачувај:
   ```bash
   for s in 1 2 3; do .venv/bin/python run.py run --method baseline --curve data/curves/ellipse.txt --seed $s --quick --out results/regresija_pre; done
   ```
2. **После** свих измена покрени исто у `results/regresija_posle` и упореди `final_error` из
   `log.json` — мора бити **бит-идентично**, не „блиско".
3. Ако имаш времена, додај и пуну проверу на познатој вредности: `egg`, seed 1, подразумевани
   буџет → `1.0846718896495868e-03` (`docs/NALAZ_04_09_gromaznost.md`).
4. Ако регресија падне: **немој да „поправљаш" резултат**. Врати измену због које је пала,
   запиши узрок у `docs/IZVESTAJ_NOC.md` и стани са мерењем. Имплементација bilevel-a може да
   остане, мерење не сме да крене.

## Ђ. Тестови (`tests/test_bilevel.py`)

Тестови су спецификација, не накнадна провера (CLAUDE.md §7). Минимум:

1. `inner_cmaes` на фиксној, ручно склопљеној валидној топологији **смањује** фитнес после
   20 итерација (не тврди колико — само да је строго мање од почетног).
2. Потрошени буџет је тачно једнак броју оцењених кандидата (укључујући и оне који падну на
   реконструкцији).
3. Иста семена → бит-идентичан `RunLog` (два узастопна `outer_ga` са истим seed-ом).
   Ако `cma` унесе недетерминизам преко неког глобалног стања, нађи узрок — не „ослабљуј" тест
   на приближну једнакост.
4. Промена N поништава кеш: `best_fitness` записа се преоцењује (провери да број позива у тој
   генерацији није мањи од броја записа).
5. Инваријанта редоследа (§16) важи за сваки скелет који оператори произведу кроз 200
   насумичних мутација — `validation.validate` не сме да падне ни на једном валидном путу.
6. `warm_start`: после `add_node` А дете има тачно две димензије више, првих `d` вредности
   средине једнако родитељевом `x*`, а последње две ширине једнаке `cma_sigma0_new`.

## Е. Шта се НЕ мења — немој ово „поправљати"

  затреба нова помоћна функција, додај је, али не мењај понашање постојећих.
- `baseline.py` — ништа. Ни рефактор, ни „заједничко извлачење" петље у надкласу. Заједничко
  се извлачи тек кад оба метода раде и кад Никола то одобри.
- Праг угла преноса (10°), граница гломазности (5.0), казна (1e9), одсецање (1e8), распоред N,
  плато-прагови — све остаје. §21 је **предлог који чека потврду**, не одлука.
- `path_health` — не дирај (§19).
- Укрштање над топологијом — не имплементирај (H2 default је само-мутација).
- Notion — ништа. Ни читање није потребно, писање је забрањено без дозволе.
- `git push`, merge у `dev` — не.

## Ж. Мерење — тек кад Д прође

1. Прво једно `--quick` покретање bilevel-a на `data/curves/ellipse.txt`, seed 1. Измери
   стварно време. Ако петља пада или виси — то је крај ноћи за мерење, пиши извештај.
2. Процени трајање пуног покретања (50 000 позива) из quick времена. Ако једно пуно покретање
   траје дуже од **25 минута**, смањи матрицу на три криве (`ellipse`, `egg`, `superellipse`)
   уместо шест. Немој смањивати буџет — буџет је јединица поређења.
3. Матрица, овим редоследом приоритета (ако време истекне, недостају задње ставке, не насумичне):

   ```
   криве:   ellipse, egg, superellipse, cassini, limacon, circle
   seed-ови: 1, 2, 3
   методи:  bilevel, baseline
   ```

   Baseline на нивоу 1 већ постоји од 03–04.09, али га **покрени изнова под овим комитом** —
   поређење мора да буде на истом коду, а §17 већ памти шта се деси кад се пореде логови из
   различитих верзија.
4. **Тврди временски оквир:** не покрећи ново мерење после 6 сати од почетка целине Ж. Оно
   што је довршено, довршено је; пиши извештај са тим.
5. Круг третирај као дегенерисан тест (§19) — резултат се наводи, али се не рачуна у закључак.

## З. Шта да оставиш иза себе

**`docs/NALAZ_05_09_bilevel.md`** — запис мерења, у стилу постојећих налаза
(`docs/NALAZ_04_09_gromaznost.md` је добар узор): питање, метод, табела свих покретања
(крива, seed, метод, коначни Chamfer, **потрошени позиви**, генерација, чворова, мин. угао
преноса, гломазност), медијане по кривој и методу, и тумачење.

У тумачењу поштуј мерни стандард овог пројекта: **разлике реда 1000× носе сигнал, разлике реда
0.6–1.2× не** (`docs/NALAZ_01_09_poza.md`). Три seed-а по ћелији је мали узорак и то мора да
пише. Ако bilevel није бољи — **тако и напиши**. H1 је хипотеза која се тестира, не тврдња која
се брани; налаз да раздвајање не помаже на кривама нивоа 1 је уредан резултат и вреди колико и
супротан.

Обавезно извештавај **пар (коначна грешка, потрошени позиви)**, не само грешку (§19) — оба
метода стају на плато пре буџета.

**Слике:** по кривој и seed-у `plot_error_curve([log_baseline, log_bilevel], …)` у
`results/poredjenje/<крива>_seed<n>.png`. X-оса су позиви симулатора, што је једина фер
јединица (README 3.3).

**`docs/DECISIONS.md` §23** — предлог закључка, изричито означен **ЧЕКА ПОТВРДУ**, по узору на
§21. Ништа што излази из мерења не сме да се закуца без Николине потврде.

**`docs/IZVESTAJ_NOC.md`** — кратак преглед за јутро: шта је урађено по целинама, шта је пало и
зашто, шта је остало, које одлуке чекају потврду, и списак комитова на грани `bilevel`. Ако си
негде стао јер је нешто противречило закљученој одлуци — то иде на врх фајла.
